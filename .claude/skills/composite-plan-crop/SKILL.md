# 종합평면도에서 한 층 잘라내기

```
도곽 지도(frame_map) → [층 고르기: 멈춤] → crop_floor(자르기 → 담는 블록 풀기 → 다시 자르기)
                  → 결과 숫자 확인 → drawing-set-intake 4절(layer_map) → parse → window-schedule-join
```

**쓰는 조건:** drawing-set-intake 인벤토리가 `composite_plan`·`structural_composite_plan` 을 제안했거나,
frame_map 이 용지 모양 도곽 2장 이상을 찾았을 때만. 파일 하나에 한 층이면 이 스킬 없이 바로 파싱한다 —
한 층 도면에 도곽 찾기를 돌리면 반복되는 작은 기호가 '도곽' 이 되어 평면이 기호 크기로 잘린다(실측: 잘라낸
기준층에 용지 모양 검사 없던 frame_map 을 돌리자 실명 기호 4 m × 1.5 m 4개를 도곽으로 골랐다). 지금은 frame_map 이
`종합평면도가 아니다` 로 멈춘다.

스크립트는 저장소 루트에서 부른다. `$S` = `.claude/skills/composite-plan-crop/scripts`.
Windows 에서는 `PYTHONIOENCODING=utf-8` 을 켜고 경로는 `C:\...` 로 준다. 입력은 DXF 다 —
DWG 면 drawing-set-intake 1절이 이미 바꿔 두었거나, 한 장만이면 `python dwg_converter.py <도면.dwg> <작업 폴더>\dxf`.
**출력(잘라낸 DXF·사이드카·frames.json)은 전부 작업 폴더(저장소 밖)에 쓴다** — 고객 xref 이름이 그대로 들어 있다.
로그도 작업 폴더로 돌린다(저장소 루트에서 `> x.log` 하면 저장소에 남는다).

## 왜 자르는가

종합평면도는 파일 하나에 층마다 A1 도곽 한 장씩을 X 로 나란히 둔다(실측: 도곽 25장, 한 장 126150×89100 mm =
A1 1/150, 변을 맞대고 붙어 있다). 그대로 파싱하면 도곽 25장의 층이 한 평면에 옆으로 늘어선 건물이 된다.

**레이어로 걸러 층을 뽑지 않는다.** 레이어는 `<층 xref>$0$<역할>` 로 층을 말해 주지만, 세대 평면과 코어는
도곽 안에 놓인 **블록 INSERT**(xref 를 bind 한 블록)라 층 레이어에 없다. 레이어로 거르면 세대가 통째로
빠진다. 그래서 **도곽(자리)** 으로 자르고, 세대·코어 블록은 **풀어서** 파서가 안의 벽·문·창을 보게 한다.

## 1. 도곽 지도

```
python $S/frame_map.py <종합.dxf> -o <작업 폴더>\frames.json [--frame-block <정규식>]
```

로드만 오래 걸린다(실측: 138 MB 에서 35~57 s). 출력:

- `frame block` — 도곽 블록. 안 주면 **용지 모양이고, 여러 번 삽입됐고, 삽입끼리 겹치지 않는 가장 큰 INSERT** 를
  고른다. 큰 순서 8개 후보를 `candidate … paper= disjoint=` 로 전부 찍는다 — 그게 근거다. 틀렸으면 `--frame-block`.
  - 왜 용지 모양(긴 변 20 m 이상, √2 ±2% — drawing-set-intake `sheet_inventory.py` 의 상수를 그대로 가져온다):
    위의 단층 사고. 한 곳에서 정해야 인벤토리가 '종합평면도' 라 한 파일을 여기서 거절하지 않는다.
  - 왜 '겹치지 않는': 코어 xref 는 여러 층 코어를 옆으로 담아 도곽만큼 크지만 도곽마다 꽂혀 서로 겹친다.
  - 왜 1% 여유: 이웃 도곽은 변을 공유하는데 bbox 가 그 변을 부동소수 오차로 준다. 여유 없이 겹침을
    판정했을 때 진짜 도곽(25장)이 '겹침' 으로 탈락하고 3번 삽입된 다른 큰 블록이 도곽으로 뽑혔다(실측).
  - 같은 크기의 도곽 변형이 같은 자리에 겹쳐 꽂혀 있을 수 있다(실측: 25장 위에 12장, 둘 다 용지 모양·겹침 없음).
    크기를 유효숫자 4자리로 비교하고 같으면 **삽입 수가 많은 쪽**을 고른다 — 전에는 부동소수 0.03 mm² 차로
    이겼을 뿐이다. 변형이 뽑히면 도곽 13장이 사라지고 번호가 밀린다. `--frame-block` 정규식이 둘 다 잡으면
    `[!] 도곽끼리 겹친다` 가 뜬다 — 이름 하나로 좁힌다.
- 도곽마다 `groups` — 층 레이어 그룹(레이어 이름의 `$0$` 앞부분)과 기준점 개수. 가장 많은 것이 그 도곽의 층이다.
  다른 그룹이 1~2개씩 섞이는 건 옆 층 표시이고, 수백 개인 둘째 그룹은 대개 같은 층의 구조(골조) xref 다(실측).
  `[!] '$0$' 층 레이어 그룹이 없다` 면 xref 를 'insert' 방식으로 bind 했거나 직접 그린 종합평면도다 — 층은 도곽의
  제목 글자로 사용자와 확인하고 3절에서 `--frame-index` 로 고른다.
- 도곽마다 `big inserts` — 정의 안 부재가 50개 이상인 블록 **전부**, 이름 × 삽입 수(부재 수) 순. 크기로 세대·코어를
  가리지 않는다: 기준층 도곽(실측)에서 세대 468~740 다음에 범례 304 · 실명 198 · `$0$` 창 블록 171 · 주열 치수 112 가
  오고 코어(70~93)는 그 뒤다. **이름으로 정한다.** `--explode` 정규식은 이 이름들에서 고른다.
- 끝의 `block roles` — 큰 블록마다 안의 역할(레이어의 마지막 `$0$` 뒤) 상위 4개. 이름이 기호처럼 보여도 벽·문·창을
  담았는지 여기서 본다(2절 `$0$` 복도 블록).

소속은 부재 하나의 **기준점**(WCS: LINE 시작점, 원·호 중심, INSERT·TEXT 삽입점, 폴리선 첫 점, MULTILEADER 내용
기준점, 나머지 bbox 중심)으로 본다.
- bbox 로 보지 않는 이유: 한글(cp949) 문자열을 담은 MULTILEADER 프록시 그래픽에서 ezdxf bbox 가 예외를
  낸다. 세대 블록 bbox 는 안의 지시선 때문에 실패해 첫 시도에서 세대 블록 7개가 전부 빠졌다. MULTILEADER 도
  bbox 로 보던 때는 39개를 '기준점 없음' 으로 지웠다(실측: 그중 3개가 기준층 도곽 안 — 창·문 부호가 흔히 이것).
- WCS 인 이유: 원·호·글자·INSERT·경량 폴리선은 좌표를 OCS 로 저장한다. 대칭(xscale<0) 삽입을 풀면 돌출 방향이
  −Z 가 되어 저장된 x 가 뒤집힌다 — 그대로 보면 대칭 세대의 벽 폴리선·문 호·실명이 도곽 밖(−x)으로 판정돼 경고
  없이 지워진다(합성 도면으로 재현. 실측 종합평면도에 음수 배율 INSERT 498개 — 이번 기준층에는 없었다).

## 2. 층을 고르고 멈춘다

frames 표를 사용자에게 보이고 **어느 도곽(층 그룹)을 자를지 yes 를 받는다.** 첫 시범은 기준층 하나다
(drawing-set-intake 2절). 기준층은 도곽 하나가 여러 층을 대표한다(짝수층·홀수층처럼 그룹 이름이 층 범위다).
같이 정한다:

- `--explode` — 풀 **담는 블록**(세대 평면·코어 xref) 이름 정규식. 반복 가능. 접두어로 준다
  (`^<세대 xref 접두어>`, `^<코어 xref 접두어>`) — 세대 타입마다 이름이 다르다.
- 풀지 않는 것: 문·창·주차 같은 **기호 블록.** 파서는 개구부를 INSERT 의 블록 이름·폭·부호로 읽는다
  (block_map, window-schedule-join). 풀면 이름 없는 선·호가 된다 — 선으로 그린 창은 레코드 69개가 실제로는
  개구부 14개였을 만큼 다루기 어렵다(실측: 기준층).
- **`$0$` 이름은 마지막 `$0$` 뒤 제 이름으로 고른다.** bind 된 xref 안의 중첩 블록은 `<xref>$0$<블록>` 이름을 달고,
  세대 접두어 정규식은 `<세대 xref>$0$<창 블록>` 에도 맞는다. 그래서 `$0$` 이름은 `--explode` 가 **마지막 `$0$`
  뒤**(블록 자신의 이름)에 맞을 때만 푼다. '마지막' 인 이유: xref 안의 xref 는 `<세대 xref>$0$<세대 xref>$0$<기호>`
  처럼 접두어가 두 번 붙는다(실측: 2개 — 첫 `$0$` 로 잘랐더니 세대 접두어에 맞아 풀렸다).
  접두어로만 맞아 안 푼 이름은 `kept as symbol` 줄과 사이드카 `spared_bind_symbols` 에 남는다.
- **`$0$` 이름도 담는 블록일 수 있다.** 실측: 층 xref 안의 복도 블록 `<층 xref>$0$<복도 블록>` 이 레이어 `0` 에
  꽂혀 있고 안에 A-WALL-DRY 80~86 · A-DOOR 최대 22(`block roles`, 도곽 5장). 안 풀면 INSERT 로 남고, layer_map 의
  마지막 줄 `.,ignore` 가 레이어 `0` 인 그 INSERT 를 통째로 버린다 — 복도 벽·문이 조용히 빠진다. `block roles` 에
  벽·문·창이 보이는 `$0$` 블록은 `--explode "<복도 블록 이름>"` 처럼 **제 이름**으로 준다(`^<층 xref>\$0\$…` 처럼
  접두어째 쓰면 제 이름에 안 맞는다).
- `--keep-block` — 무엇보다 먼저 이긴다(반복 가능). 줘도 위의 `$0$` 규칙은 그대로다(예전엔 하나만 줘도 기본값이
  통째로 바뀌어 기호까지 풀렸다).

## 3. 자르기

```
python $S/crop_floor.py --src <종합.dxf> --dst <작업 폴더>\<층>.dxf --floor-group "<층 xref>" --explode "^<세대 xref 접두어>" --explode "^<코어 xref 접두어>"
```

`--floor-group` 대신 `--frame-index N`(frames 표 번호)도 된다. 시간(실측: 138 MB → 약 5,300 부재): 65~105 s.

하는 일과 이유:

1. **자르기** — 기준점이 도곽 안인 모델공간 부재만 남긴다. 도곽 판정은 원점(왼쪽 아래) 쪽으로 1e-6 만큼 민
   반열린 구간이다. xref 는 흔히 **도곽 원점에** 꽂힌다(실측: 코어 xref 4개 전부, y = −3e-10 오차). 오차를
   흡수하지 않으면 도곽 bbox 반올림에 따라 코어가 들어왔다 빠졌다 하고, 빠지면 코어 벽(S-CONC 111개 등)
   330개가 조용히 사라진다. 오른쪽 모서리는 이웃 도곽의 원점이라 이웃 것이다.
2. **담는 블록 풀기** — 블록 **정의**의 부재마다 `copy()` → `transform(삽입 행렬)` → 모델공간에 추가.
   `explode()` 는 블록 안 부재 하나에서 통째로 실패하고, `virtual_entities()` 는 복사 못 하는 부재(동적 블록의
   문자 등)를 조용히 건너뛴다. **확장 사전(동적 블록 표현·XCLIP)을 단 중첩 INSERT** 는 `copy()` 가 실패한다(실측:
   431개 — 속성과는 무관하다. 담는 블록 안 중첩 INSERT 1,191개 중 속성 단 것 0). 같은 블록을 같은 속성(레이어·색·
   선종류·돌출·배율·회전)으로 새로 꽂고 ATTRIB 을 옮긴다(`explode:blockref_fallback`, 실측: 기준층 111 · 짝수 기준층
   120). 확장 사전은 옮기지 않는다 — 동적 블록의 현재 상태 표현과 XCLIP 이 여기서 사라진다.
3. **XCLIP 은 적용하지 않고 센다.** 담는 블록 INSERT 나 그 안의 INSERT 에 XCLIP(ACAD_FILTER)이 걸려 있으면 시트는
   일부를 가렸는데 풀면 블록 정의 전체가 들어온다. `[!] XCLIP 무시` 와 사이드카 `containers[].xclip`·
   `counts['xclip:*']` 로 알린다. 경계 좌표의 규약을 실측으로 확인하지 못해 자르지 않는다 — 뜨면 그 도곽을 원본
   시트와 눈으로 대조한다(실측: 이 종합평면도에서 XCLIP 된 담는 블록 11개 — 기준층 도곽 0, 상층 도곽 하나에서 2개가
   `[!] XCLIP 무시` 로 떴다).
4. **다시 자르기** — 코어 xref 하나에 여러 층 코어가 옆으로 들어 있어 풀면 이웃 도곽까지 나간다(실측: 풀기만
   하면 모델 폭 174 m > 도곽 126 m).
5. **저장** — `<층>.dxf`(도곽 좌표 그대로) + `<층>.inserts.json`: 푼 담는 블록마다 이름·레이어·삽입점·회전·
   x/y/z 배율·돌출·XCLIP 여부·4x4 행렬(`matrix`, ezdxf 행 벡터 규약 — 이동은 넷째 행)·회차, 그리고 `frame_bbox`·
   `sheet_offset`·`counts`·`spared_bind_symbols`.

### 출력 읽기

| 줄 | 뜻 | 이상하면 |
|---|---|---|
| `[!] 층 그룹이 도곽 여러 장에 걸친다` | 그룹 부재가 가장 많은 도곽을 쓴다(실측: 581 대 18 — 다른 시트의 표시) | 비슷한 수로 갈리면 `--frame-index` 로 정한다 |
| `crop: … outside_frame` · `crop:no_anchor:<TYPE>` | 도곽 밖 / 기준점을 못 구한 부재, 타입별(실측: OLE2FRAME 1) | 벽·문·창 타입이거나 수십 이상이면 그 타입의 기준점을 `anchor()` 에 더한다 |
| `round N: exploded K` | 회차별로 푼 담는 블록 수(실측 기준층: 1회차 세대 7 + 코어·코어 골조 4, 2회차 세대 안 골조 블록 3. 짝수 기준층은 복도까지 1회차 12) | frames 의 `big inserts` 에서 `--explode` 에 맞는 이름 수와 대조 — 코어도 목록에 있다 |
| `kept as symbol ('$0$' …)` | 접두어로만 맞아 INSERT 로 남긴 `$0$` 이름 수 | `block roles` 에 벽이 있는 이름이면 제 이름으로 `--explode` |
| `[!] XCLIP 무시` | 가린 부분까지 들어왔다(3번) | 원본 시트와 대조, 남는 부분은 사람에게 보고 |
| `explode:failed:<TYPE>` | 복사·변환 못 한 부재(실측 0개) | 벽·문·창 타입이면 보고한다 |
| `reclip: dropped N {…:<TYPE>}` | 풀어서 도곽 밖으로 나간 부재, 타입별(실측: INSERT 11) | LINE·LWPOLYLINE·ARC 가 수십 이상이면 도곽에 걸친 세대가 잘렸거나 기준점 문제 — 원본 시트와 대조 |
| `9회차 뒤에도 담는 블록이 남았다` | 정규식이 자기를 담는 블록에 맞는다 | 정규식을 좁힌다 |
| `sheet_offset` | 도곽 원점. **좌표는 아직 시트 좌표다**(실측: x ≈ 2,018 m) | — |

잘라낸 층을 한 번 눈으로 본다(drawing-set-intake 8절 미리보기). 도곽 안 세대 수·코어·복도가 원본 시트와 같은지.

## 하지 말 것

- 한 층 도면에 쓰기 — 반복 기호가 도곽이 된다. `종합평면도가 아니다` 가 뜨면 멈추고 drawing-set-intake 로 간다.
- 레이어로 층 뽑기 — 세대·코어가 빠진다.
- 모든 블록 풀기 — 문·창이 이름 없는 선이 되어 블록 기준 개구부 조인이 끊긴다.
- `$0$` 이름이면 무조건 기호로 보기 — 복도처럼 벽을 담은 블록이 레이어 `0` 째 버려진다. `block roles` 로 본다.
- **담는 블록을 내용으로 도곽에 넣기.** 시도했다: 삽입점이 다른 도곽이어도 안의 부재가 이 도곽에 떨어지면
  풀도록 했더니, 5개 도곽 떨어진 층의 세대 블록 정의 안에 섞인 문 블록 하나(세대 원점에서 약 636 m)와 다른 층
  코어의 승강기 기호가 이 층에 들어왔다. 소속은 삽입점으로, 원점 오차만 흡수한다.
- 도곽 판정을 닫힌 구간·여유 없이 — 이웃 도곽 원점의 블록이 두 층에 다 들어가거나, 원점 코어가 빠진다.
- OCS 좌표(`dxf.center`·`dxf.insert`·`vertices()`)를 그대로 기준점으로 — 대칭 세대가 사라진다. `anchor()` 를 쓴다.
- 잘라낸 DXF·frames.json·사이드카·실제 xref/블록 이름을 저장소에 두기. 스킬·커밋 메시지에는
  `<층 xref>`·`<세대 xref 접두어>` 같은 자리표시만 쓴다(저장소는 공개다 — drawing-set-intake '고객 자료 위생').
- 층마다 임시 크롭 스크립트 작성 — 이 두 스크립트로 안 되는 도면이면 그 차이를 보고한다.

# 개구부 실패 모드 — 증상 → 원인 → 조치

출처 표기: **(시범)** = 첫 실무 도면 세트의 종합평면도 기준층에서 잰 값, **(시험)** = 이 스킬 스크립트를 같은 도면에
다시 돌려 잰 값. 파서 쪽 원인은 전부 저장소에서 고쳐졌다 — 다시 보이면 **파서 회귀**이므로 지표를 들고 보고한다.

| 증상(눈에 보이는 것) | 지표 | 원인 | 조치 |
|---|---|---|---|
| 창 자리에 **반쪽짜리 창대 벽·인방 토막** | 블록 원 `width_source=default`, `anchor` 없음 | 블록 창 67개가 전부 폭 900 을 **삽입점**(= 창의 한쪽 끝)에 두었다 → 39곳에 반쪽 토막 (시범) | block_map 에 폭을 선언한다(`opening_inventory` 의 폭 근거). 선언 폭이 있으면 파서가 블록 가운데로 옮긴다 |
| **창 폭이 다 900** | `openings_dims_assumed.width`, `width_source=default` | 아무도 폭을 말하지 않았다 — 900 은 가정 | 폭 근거 우선순위: 블록 안 `W:` 글자 > 미터 글자 > 이름 끝 `-1200`(파서 규칙) > 이름 속 3~4자리 수(낮은 확신) > 로컬 범위 |
| 창짝이 **겹겹이** 선다(최대 9장) | 선 개구부(`kind=polyline`)가 수십 개 | 선으로 그린 창의 틀·유리선이 각각 개구부가 됐다 — 선 레코드 69개가 실제로는 개구부 14개 (시범) | 파서가 평행선을 합친다(수직 거리 ≤ 400mm · 긴 쪽의 80% 이상 겹침 · 같은 종류). 남는 것은 선 도면의 한계 — 치수는 가정으로 보고된다 |
| 문설주·**스윙 호가 벽을 뚫는다** | 작은 선 개구부 | 문틀 옆선·열림 호가 개구부가 됐다 | 파서가 문설주 선과 선언된 문의 스윙 호를 버린다(`opening_fragments_dropped`) |
| **현관문이 통째로 사라졌다** | 문 블록인데 개구부 없음 | 문 철물 원(r≈8)을 개구부로 잡고 조각으로 버렸다 — 세대 현관문 6개 전부 (시범) | 파서가 개구부일 수 없는 크기의 원을 무시한다 |
| 일람을 넣자 **개구부가 늘었다** | `source=wall_gap_match` 증가 | 이미 블록으로 놓인 부호까지 벽 끊김 폭 매칭이 다시 놓았다 | 파서가 놓인 부호를 끊김 매칭에서 뺀다 |
| **창 머리가 벽 위로** 뚫고 나간다 | 창 `sill` 900 + 높이 2200 | 카드에서 창대를 못 읽어 900 을 가정했다 — `F.L` 글자가 자기 선보다 ~220mm **위**, 카드 상자보다 ~1.1m **왼쪽**에 있어 좁은 창으로는 안 잡혔다 (시범) | `card_extract` 의 F.L 규칙(글자보다 100mm 이상 아래의 가장 가까운 사슬 높이). 실측 창대: 거실·침실 2200 창 240 · 발코니 쪽 320 · 작은 창 1190/1270 (시험, 245장) |
| 점검구형 문이 **바닥부터** 뚫렸다 | 문 일람 H1 > 0 | 파서·빌더는 **문의 문턱을 무시**한다 — 바닥에서 600 뜬 700x1500 문 (시범) | 창으로 선언(`subtype=window`, 창대 = H1). IFC 에서는 IfcWindow 가 된다 — 검토표에 적는다 |
| 미서기문에 **창대가 붙었다** / 창으로 나왔다 | 부호 접두 PD | PD 는 바닥부터 여는 문이다. 창 블록으로 그려져 있어 창으로 잘못 읽었다 | 종류는 부호 접두로(저장소 `schedule_io` 규약: PW·AG→창, 그 밖→문). 창 블록과 맞추려면 `--either-kinds PD` |
| 같은 부호인데 **창대가 방마다 다르다** | — | 조인은 부호 하나로만 한다 — 한 부호에 창대 하나 | 흔한 쪽이 맨 부호, 나머지는 `부호@실명`(예: 발코니 쪽 320 · 침실 240) |
| 일람 높이가 **안 먹는다** | `dims_source` 는 schedule 인데 높이가 다르다 | block_map 에 height 를 적었다 → `overrides` → 일람을 이긴다 | block_map 의 height 는 **비운다** |
| xlsx 를 거치자 **창대 900** 이 생겼다 | 일람 행 `sill` 900 | `export_schedule_xlsx` 는 **키가 빠진** 창대에 기본값을 채운다 | 모르는 창대는 `"sill": null` 을 명시한다(`schedule_to_xlsx` 가 왕복으로 확인) |
| 창으로 선언한 문이 **다시 문**이 됐다 | xlsx 종류 칸 | 종류 칸이 비면 읽을 때 부호 접두로 추정한다(FSD-3 → 문) | 행마다 `subtype` 을 채운다 — xlsx 종류 칸은 그것에서 만든다 |
| block_map 을 넣자 **다른 블록이 사라지거나 바뀌었다** | 카테고리 수 변화 | block_map 은 기본 블록 규칙을 **대체**한다 | 제안 CSV 맨 아래에 기본 규칙(또는 기존 block_map)을 그대로 옮긴다 |
| 다시 변환했더니 **공용 문 선언이 안 먹는다** | `*U…` 행이 한 번도 안 걸림 | 동적 블록의 익명 이름 `*U…` 는 DWG→DXF 변환마다 바뀐다 | 재변환하면 인벤토리·제안을 다시 돌린다. 동적 블록 원래 이름은 인벤토리 `dyn` 에 있다 |
| 같은 창이 **9개** 겹쳐 있다 | 인벤토리 `stacked` | 자르기 산출물 — 같은 이름·같은 삽입점 INSERT 가 여러 번 (시범: 두 세대 형식의 실외기실 창 9·8개) | 개수는 **고유 위치**로 센다(인벤토리가 접는다) |
| 창 하나가 **10m 넘는다** | 인벤토리 폭 > `--max-width` | 외벽을 따라 선 창틀 선 묶음 블록 — 창 하나가 아니다 | 제안은 `검토` 로 두고 ignore 줄을 주석으로만 낸다. 제외는 사람이 결정한다(시범에서 사용자 결정) |
| 동적 문 블록 **폭 글자를 못 읽는다** | 미터 근거 없음 | `virtual_entities()` 는 복사 불가 엔티티(동적 블록 안 '0.7')를 건너뛴다 | 블록 **정의**를 직접 걷는다(`dxfwalk.block_contents`) |
| 실명 라벨이 **일부만** 잡힌다 | `with_room` 이 적다 | 라벨 블록의 `virtual_entities()` 가 중간에 예외로 멈춘다 (시범) | 정의를 걷는다. 라벨은 글자 크기별 사본 3벌(레이어 이름 끝이 축척 표시)이 겹쳐 있으니 `--room-layer` 로 하나만(`--list-room-blocks`) |
| 안내도 부호가 **엉뚱한 자리**에 떨어진다 | 축 정렬 잔차는 0 | 잘라낸 층 평면에 옆 도곽의 축망이 한 벌 더 있어 이름마다 좌표가 둘 — 평균을 내면 도곽 반 폭(63,075mm)만큼 틀린 이동량이 잔차 0 으로 나온다 (시험) | `axis_align` 은 동률이면 값을 안 낸다 → `--region-a` 로 층 내용이 있는 한 벌만 |
| 세대 블록이 **전부 공용**으로 나오고 제안이 거의 다 미결 | 인벤토리 `unit` 이 전부 null | 정규식을 큰따옴표로 줬다 — Bash 는 `\$0\$` 를 `$0$` 로, PowerShell 은 `$0` 을 변수로 바꾼다. 시험: 지정 58 → 5, 미결 54 | 정규식은 작은따옴표로. 인벤토리는 `--unit-regex` 가 한 이름에도 안 맞으면 멈춘다 |
| 미결 문이 **두 배 가까이 넓게** 뚫렸다 | 미결 행 폭 근거 `extent` | 문 블록의 로컬 범위에는 스윙 호가 들어간다(시험: 1395 ↔ 문짝 750). 첫 제안은 그 폭을 선언했다 | 폭 근거가 `extent`·`name_loose` 뿐인 미결 행은 주석으로만 낸다. 후보는 그 형식의 문 카드 전부 |
| 새 block_map 을 줬는데 **미리보기가 그대로** | — | 기존 `.mep` 폴더는 저장된 원본 설정을 쓴다 · 떠 있는 서버는 옛 파서 모듈을 들고 있다 | 새 block_map·일람이면 **새 프로젝트 폴더**. 파서를 고쳤으면 서버를 다시 띄운다 |

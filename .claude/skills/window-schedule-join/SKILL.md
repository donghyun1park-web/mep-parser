# 창호일람 조인 — 블록 종류가 부호를 선언한다

평면도에는 창 **높이·창대가 없다**(폭·위치뿐). 실무 도면은 평면에 창호 부호조차 없는 경우가 흔하다 —
첫 실무 도면 세트의 기준층 평면에는 부호가 **하나도 없었다**. 그때 열쇠는 **블록 종류**다: 세대 형식마다 같은
창 블록이 쓰이고, 그 블록이 어느 부호인지 사람이 한 번 선언하면(block_map `opts: mark=`) 파서가 창호일람
xlsx 의 같은 부호 행에서 높이·창대·종류를 받는다.

원칙(저장소 규약 그대로): 파서는 이름으로 재분류하지 않는다. 값은 **선언(block_map/layer_map opts)이나 잰 기하**
에서만 온다. 이 스킬의 스크립트는 결정론적 **제안표**를 만들 뿐이고, 부호 하나하나는 **사람이 확인할 선언**이다.
LLM 은 그리지 않는다 — 모호한 행의 근거를 정리하고 검증 패스를 돌린다.

```
① 진단(지표) → ② 평면 블록 인벤토리 → ③ 일람 출처(카드 · 문 일람 · 안내도) → ④ 제안(block_map + 일람 행 + 검토표)
  → ⑤ 독립 검증(새 에이전트) → ⑥ xlsx · 새 프로젝트 폴더로 파싱 · 지표 · IFC → ⑦ 검토표를 사람에게
```

앞 단계: 도면 세트는 **drawing-set-intake**, 종합평면도에서 층 자르기는 **composite-plan-crop** 이 먼저다.
레이어가 안 잡히면 **map-layers**, 빌드가 실패하면 **verify-model**.

스크립트는 저장소 루트에서 부른다. `$S` = `.claude/skills/window-schedule-join/scripts`,
`$I` = `.claude/skills/drawing-set-intake/scripts`. Windows 는 `PYTHONIOENCODING=utf-8`, 경로는 `C:\...`.
모든 출력은 **저장소 밖 작업 폴더**(`<작업 폴더>/decl/`)에 둔다 — 블록·xref 이름이 곧 현장 식별자다. 그래서 출력
인자(`--out`·`--out-dir`·xlsx)는 필수이고, 저장소 안 경로면 스크립트가 멈춘다(저장소 루트에서 `decl/…` 로 부르면
제안 CSV 가 공개 저장소에 떨어진다 — `.gitignore` 가 csv·json·md 를 안 거른다).
**정규식 인자는 작은따옴표로 준다.** 큰따옴표면 Bash 는 `\$0\$` 를 `$0$` 로 바꾸고 PowerShell 은 `$0` 을 변수로
읽는다 — 시험: 큰따옴표 명령의 인벤토리는 세대 형식이 전부 비었고, 그걸 먹은 제안은 지정 58 → 5 로 무너졌다.
스크립트마다 `--selftest` 가 있다(합성 도면, 고객 자료 없음). 처음 쓰는 PC 에서 한 번씩 돌린다. 엔티티 하나가 읽기에
실패하면 건너뛰고 `읽기 실패 {…}` 로 센다(시험: 카드·문 일람·평면 모두 0) — 0 이 아니면 빠진 글자가 창대·실명을 비웠을 수 있다.

## ① 진단 — 숫자부터, 눈은 그다음

```
python $I/parse_summary.py <층.dxf> --layer-map <lm.csv> [--block-map <bm.csv>] [--schedule <일람.xlsx>] --out <작업 폴더>/<이름>
python ifc_builder.py <작업 폴더>/<이름>.geometry.json <작업 폴더>/<이름>.ifc
python $I/build_summary.py <작업 폴더>/<이름>
```

증상은 `references/failure_modes.md` 표와 대조한다. 먼저 볼 것:

| 지표 | 뜻 |
|---|---|
| 블록 원 `width_source=default` | 폭을 아무도 말하지 않아 900 가정 → 반쪽 창대·인방 토막의 원인 |
| `openings_dims_assumed` height/sill | 일람 조인이 안 된 개구부 수 |
| `opening_kind` polyline 수 | 선으로 그린 창(조각은 파서가 합친다 — 치수는 가정으로 남는다) |
| `no_host_reason` | `wall_open_at_this_span` = 도면이 창 자리에서 벽을 끊음(정상) · `no_wall_on_this_line` = 확인 |
| `panels_without_host_cut` · `verify` | IFC 에 창짝만 서고 벽이 안 뚫린 곳 · V106 개수 |

**subtype 을 선언하면 개구부가 더 이상해 보일 수 있다** — 원래 있던 결함이 보이게 된 것이다(시범: 블록 창 67개가
전부 삽입점에 폭 900 → 반쪽 토막 39곳, 선 레코드 69개가 실제로 개구부 14개, 현관문 6개 사라짐). 그래서
고칠 때마다 같은 지표를 다시 찍고 **전후 숫자**를 사용자에게 보인다. 파서 쪽 원인은 고쳐져 있다 — 다시 보이면
파서 회귀로 보고한다.

## ② 평면 블록 인벤토리

INSERT 이름부터 눈으로 본다(`python dxf_parser.py <층.dxf> --scan`). 세대 블록은 xref bind 이름
`<unit xref prefix>-<형식>-<variant>$0$<block>` 꼴이었다 → 형식을 잡는 정규식을 쓴다. 실명 라벨 블록과 글자 크기
레이어는 `--list-room-blocks` 가 찾는다(짧은 한글 글자가 많은 블록을 레이어·글자 높이별로 — 시험: 후보 1개, 사본 3벌).

```
python $S/opening_inventory.py <층.dxf> --list-room-blocks
python $S/opening_inventory.py <층.dxf> --unit-regex '^[^$]*-(\d+[A-Z]?)-[^$]*\$0\$' \
    --room-block '<room label block>' --room-layer '<한 글자 크기 레이어>$' --out <작업 폴더>/decl/inv.json
```

`--unit-regex` 가 몇 개 이름에 맞았는지 찍고, 하나도 안 맞으면 멈춘다(시험: 57/73 — 나머지 16 은 공용 블록).
실명 라벨이 하나도 안 잡혀도 멈춘다.

- 고르는 INSERT = 레이어 꼬리가 `--opening-layers`(기본 `A-(WIN|DOOR)$`)에 맞거나 블록 이름이 기본 블록 규칙으로
  opening 인 것 — **파서가 개구부로 보는 그 집합**이다. 레이어만 보면 벽 레이어에 놓인 창(이중창 블록)·전용
  레이어의 대피창·문 블록을 놓친다(시험: 레이어로 INSERT 84개·고유 69, 블록 규칙으로만 잡히는 것이 4개 더).
- **같은 이름·같은 삽입점은 한 개로 접고 `stacked` 로 센다** — 자르기 산출물로 같은 창이 9개·8개 겹쳐 있었다.
- 폭 근거는 전부 기록하고 이 순서로 고른다: 블록 정의(중첩 포함) 안의 `W:1,800` 글자(`label`) > 동적 문 블록의
  미터 글자 `0.7`(`metre`) > 파서와 같은 이름 규칙 — 끝의 `-1200`(`name`) > 이름 어디든 3~4자리 수(`name_loose`) >
  로컬 X 범위(`extent`). `name_loose` 는 연도·코드일 수 있어 검토표가 '낮음'으로 표시한다(시험: 이름 폭 14종이 전부
  이것이었고 전부 카드와 맞았다 — 그래도 사람이 이름을 한 번 본다). 범위는 프레임 바깥까지라 20mm 크거나(1820 ↔
  W:1,800) 블록 축이 창과 달라 엉뚱하고(510 ↔ W:1,200), 문 블록은 스윙 호까지 들어가 크게 틀린다(시험: 1395 ↔ 문짝
  750). 익명 블록 번호(`*U…`·bind 된 익명 이름)는 폭이 아니다.
- 블록 정의를 **직접** 걷는다: `virtual_entities()` 는 동적 블록의 복사 불가 글자(미터 폭)를 건너뛰고, 실명 라벨
  블록에서는 중간에 예외로 멈춰 라벨 일부만 나왔다.
- 실명 라벨은 한 블록에 전 세대 라벨이 **글자 크기별 사본 3벌**(레이어 이름 끝이 축척 표시)로 겹쳐 있었다 —
  `--room-layer` 로 하나만(시범은 글자 높이가 가장 큰 벌을 썼다). 공용 설비실 약어(PS·AD·EPS·TPS·DS)는 기본으로 뺀다.
- `*U…` 는 동적 블록의 익명 이름이라 **DWG→DXF 변환마다 바뀐다**. 원래 이름은 `dyn` 에 있다.

## ③ 일람 출처 추출

### 3a. 창호전개도(세대 카드) — 부호 · W·H · 창대 · 실명 · 형식

카드 = 부호 기호 블록(ATTRIB 종류 `PW`… + 일련번호 `18x22`) + 입면 + 세로 치수 사슬 + `F.L` 글자.
일련번호가 곧 100mm 단위 크기다(`18x22` = 1800x2200, `7.5x22.4` = 750x2240).

```
python $S/card_extract.py <카드.dxf> --list-symbols                                     # 부호 기호 블록 찾기
python $S/card_extract.py <카드.dxf> --symbol-block '<symbol block>' --dump 0          # 한 장을 기호 기준으로 본다
python $S/card_extract.py <카드.dxf> --symbol-block '<symbol block>' --field room=<dy> --field name=<dy> \
    --title-regex '\((?P<unit>\d+)㎡(?P<u2>\S*) (?P<variant>\S+)\)' --out <작업 폴더>/decl/cards.json
```

- `--list-symbols` = ATTRIB 값이 `18x22` 꼴인 INSERT 이름을 쓰인 수로(시험: 후보 1개, 245회 = 카드 245장).
- `--dump` 로 카드 칸의 dy 를 재서 `--field` 로 준다: `room` = 위치 칸(실명), `name` = **카드 안 품명 줄**
  (예: `철재여닫이문(60분방화문)`). 품명은 시트 제목(도곽 표제 — `--title-regex` 가 읽는다)과 다른 것이다. 시험: 품명
  dy 0 · 위치 dy −6991 (중앙정렬 글자는 정렬점 기준이라 삽입점으로 잰 값과 다르다). 태그는 값 모양으로 스스로 고른다.
- `W 불일치 N` = 일련번호 W 와 카드 가로 치수 최대값이 다른 카드(`w_consistent=false`, 시험: 14장 — 예: `PW 9x12.5`
  인데 가로 치수 3600). **일련번호가 크기다** — 가로 치수는 대조용일 뿐이다. 그 카드가 제안에 쓰이면 검토표
  근거에 ★ 로 붙는다(시험: 2행) — 카드를 렌더해 눈으로 본다.
- ★ **F.L 규칙.** `F.L` 글자는 자기 선보다 ~220mm **위**에 있고(사이에 삼각형) 카드 상자보다 ~1.1m 왼쪽에 있기도
  하다. 첫 추출은 카드 안쪽만 찾다가 이 글자를 놓쳐 창대 900 을 가정했고, 창 머리가 벽 위로 나갔다. 스크립트는 기호
  왼쪽 2.5m 까지 글자를 찾고, **글자보다 100mm 이상 아래의 가장 가까운 사슬 높이**를 F.L 선으로 잡는다. 옆 카드의
  글자도 창에 들어오므로 글자-선 사이가 가장 좁은 글자를 고른다(시험 245장: 220mm 가 225장 중 175장, 글자는
  기호 왼쪽 1.3~2.2m 141장 · 오른쪽 4.4~5.2m 84장 — 한 도면에 두 배치가 섞여 있다).
- 창 하단은 사슬에서 (b, b+H) 짝으로 찾는다. F.L 글자가 없으면 **사슬 폴백**: 창 아래 구간이 정확히 둘이면
  [S.L→F.L, F.L→창] 으로 읽고 `sill_basis=chain` + 사유를 남긴다 — `120 / 240 / 창` 은 창대 240 이다(F.L·S.L 둘 다
  표시된 카드에서 확인). 시험: F.L 225 · chain 12 · 못 읽음 8(치수 사슬을 못 찾은 한 시트).
- 세대 형식은 시트 제목에서(도곽 우하단 표제). `--title-regex` 는 **모든 시트 제목에 맞아야** 한다 — 일부만 맞으면
  카드가 옆 시트 제목에 붙는다. 평면형(variant)은 ④에서 고른다.
- 결과 대조(시험): 기준층에 쓰인 부호의 창대가 사람이 확정한 값과 전부 같았다 — 거실·침실 2200 창 240,
  발코니·실외기실 쪽 320, 작은 창 1190/1270, 문 0.

### 3b. 문 일람표 — 층별 공용 문

```
python $S/door_table.py <문일람.dxf> --floor-filter '<대상 층 표기 정규식>' --out <작업 폴더>/decl/doors.json
```

- 표는 선이 아니라 글자 칸이다. `FLOOR` 머리 칸 하나 = 표 덩어리 하나(시험: 10개 — 두 줄에 8개·2개가 옆으로). 머리는 2단
  (`ARCHI`/`MARK`, `DOOR`/`WIDTH`)을 위→아래로 잇는다.
- 데이터 칸은 왼쪽 부착 MTEXT 가 섞여 있다 — **칸 가운데(부착점+폭)** 로 열을 고른다. 삽입점으로 고르면 FROM
  글자가 옆 MARK 열로 간다. 칸 글자 크기(±20%)가 아닌 글자는 버린다(도곽 격자 기호 `A` 가 `FSD-3 A` 로 붙었다).
- 문 범례표(부호 · W x H · W1 · **H1**)에서 부호별 H1 을 붙인다. H1 = 바닥에서 문 아래까지(점검구형 문).
- 시험(대상 층 필터): 17행 — FSD-1 ×4 1100x2100 · FSD-3 ×11 700x1500 H1 600 · AD-3-1 ×2 1100x2100.
- 세대 문 일람(형식별 표)처럼 머리가 다른 표는 열이 섞일 수 있다 — 그 표를 쓸 때는 행을 눈으로 확인한다.

### 3c. 창호 안내도 — 평면 위 부호 지시선(공용부)

안내도는 층 평면과 좌표가 다르다. **통심선 이름**(X1..X10, Y1..Y7)으로 평행이동을 잰다(시범: 축 17개, 잔차 0):

```
python $S/axis_align.py <층.dxf> <안내도.dxf> --region-b x0,y0,x1,y1      # 안내도의 해당 층 패널만
```

- 잘라낸 층 평면에 **옆 도곽의 축망이 한 벌 더** 딸려 있었다(도곽 폭 126,150mm 떨어져). 이름마다 좌표가 둘이면
  후보가 동률이라 도구는 값을 내지 않고 두 벌을 보여 준다 → `--region-a` 로 층 내용이 있는 한 벌만 준다. 중앙값을
  냈다면 도곽 반 폭(63,075mm)만큼 틀린 값이 **잔차 0** 으로 나왔다(시험). 한 벌만 주면 축 17개 잔차 0 으로 시범 때
  구한 이동량과 같았다(시험, 안내도 279MB 포함 약 2분).

옮긴 뒤 지시선 끝은 개구부에서 25~1500mm 떨어져 있었다 — 자동 매칭하지 말고 부호별로 사람이 확인한다. 공용 문은
대개 문 일람표(3b)의 개수 일치로 충분했고 안내도는 확인용이었다.

**세대 좌표로 그린 부호**(단위세대 평면에만 부호가 있을 때)는 통심선이 아니라 **세대 삽입 행렬**로 옮긴다.
composite-plan-crop 이 풀어 버린 세대 블록의 행렬은 DXF 에 안 남고 사이드카(`<층>.inserts.json` 의 `containers[]`
— `name`·`insert`·`matrix`)에만 있다. 같은 세대 xref 이름의 행마다 한 번씩 `Matrix44(*c["matrix"]).transform(p)`
(`ezdxf.math`)로 옮긴다 — 세대가 층에 여러 번 놓였으면 부호도 여러 벌이 된다. 세대 xref 가 그 단위세대 평면
파일 자체일 때만 좌표계가 같다 — 옮긴 부호 하나를 창 블록 자리와 먼저 대조한다. 시범 기준층은 블록 종류가 열쇠라
이 경로를 쓰지 않았다.

## ④ 제안 — block_map 행 · 일람 행 · 검토표

```
python $S/propose_block_map.py --inventory <작업 폴더>/decl/inv.json --cards <작업 폴더>/decl/cards.json \
    --doors <작업 폴더>/decl/doors.json --card-variant '<평면과 같은 variant>' \
    --unit-alias <평면 형식>=<카드 형식> --either-kinds PD --out-dir <작업 폴더>/decl
```

카드 고르기(같은 세대 형식 안에서 차례로 좁힌다 — 하나 남으면 지정, 아니면 **미결**로 후보만):
① |평면 폭 − 카드 W| ≤ 50 ② 창/문 일치 ③ 블록 이름 토큰이 카드 종류·실명·품명에 있으면 그것만(`실외기`→실외기실,
`FSD`→FSD, `이중창`→품명) ④ 가까운 실명 라벨(4m 안, 가까운 둘)이 카드 실명과 맞는 것 — 인스턴스 전부가 맞아야 한다.
공용 블록은 문 일람 행 중 폭이 맞는 부호, 여럿이면 **평면 개수 = 일람 행 수**인 부호.

규칙마다 이유:

- **height 는 비운다.** block_map 의 height 는 `overrides` 로 가서 일람 높이를 이긴다. 높이·창대는 일람에서만.
- **mark 는 후보가 정확히 하나일 때만.** 미결 행은 폭 근거가 믿을 만할 때(`label`·`metre`·`name`)만 폭·종류를
  선언한다. `extent`·`name_loose` 뿐이면 그 행을 **주석으로만** 낸다 — 틀린 폭 선언은 선언이 없는 것보다 나쁘다
  (시험: 첫 제안은 미결 문을 범위 폭 1395 로 선언했다 — 문짝은 750). 문 쪽 미결은 폭순이 아니라 **그 형식의 문 카드
  전부**를 후보로 적는다(범위 폭에 가까운 카드 셋을 고르자 정답 카드가 빠졌다).
- **확신**: `extent` 폭은 '낮음(폭=범위)', `name_loose` 폭은 '낮음(폭=이름 속 숫자)', 근거가 폭·종류뿐이면 '높음',
  이름 토큰·실명으로 좁혔으면 '중간'. 낮음·중간·미결·검토가 ⑦의 질문이 된다.
- **맨 아래에 기본 블록 규칙을 그대로 옮긴다**(`--default-block-rules` 로 기존 block_map 도 가능). block_map 은 기본
  규칙을 대체한다 — 안 옮기면 다른 블록의 분류가 바뀐다. 제안 CSV 는 저장 직후 `load_layer_map` 으로 읽어 본다.
- **행은 전체 이름을 `re.escape` 로, 세대 형식별로.** 같은 익명 블록이 형식마다 다른 부호다(시험: 같은 900 창
  블록이 한 형식에선 PW 9x5, 다른 네 형식에선 PW 9x12.5).
- **종류는 부호 접두로**(저장소 `schedule_io` 규약: PW·AG → 창, 그 밖 → 문). PD 는 바닥부터 여는 미서기문인데 창
  블록으로 그려져 있다 → `--either-kinds PD` 로 매칭만 허용하고, 같은 쪽 종류 후보가 있으면 그쪽을 먼저 둔다.
- **H1 > 0 인 문은 창으로 선언**(창대 = H1). 파서·빌더는 문의 문턱을 무시하고 바닥부터 뚫는다. IFC 에서는 IfcWindow
  가 되므로 검토표에 적는다.
- **같은 부호가 창대만 다르게 두 번 쓰이면** 흔한 쪽이 맨 부호, 나머지는 `부호@실명`(조인은 부호 하나로만 한다).
  카드에 실명이 없으면 실명 자리에 세대 형식이 들어가 한정이 겹칠 수 있다 → `부호@실명-창대`, 그래도 겹치면 미결.
- 평면 형식 이름과 카드 시트 이름이 다를 수 있다(평면은 `<면적>A`, 시트 제목엔 A 없음) → `--unit-alias`. 폭이 `--max-width`(6m)를
  넘는 블록은 창 하나가 아닐 수 있어 `검토` — ignore 줄은 주석으로만 내고 제외는 사람이 정한다.

시험(기준층): 블록 형식 60 → 지정 58 · 미결 1 · 검토 1. 제안 CSV 의 살아 있는 opening 행 60(지정 58 + 기본 규칙 2)이
사람이 확정한 block_map 과 **폭·종류·부호까지 전부 같았고** 다른 행은 0. 확정본에만 있는 1행 = 미결 문(폭 근거가 스윙
호까지 든 범위 1395 — 사람은 문짝 750 카드로 정했다). 제안은 그 행을 주석으로 내고, 검토표 후보에 그 750 카드가 있다.
검토 1 = 외벽을 따라 선 10.5m 창틀 선 블록(사람이 제외로 정했다 — 제안은 ignore 줄을 주석으로). 제안의 일람 행 19개도
W·H·창대·종류·수량이 확정본과 같았다(확정본에는 그 문 1행이 더 있다).

## ⑤ 독립 검증 — 건너뛰지 않는다

제안을 만든 흐름과 **다른** 에이전트(새 서브에이전트)에게 원본 DXF·인벤토리·검토표만 주고, 행마다 원본에서 다시
유도하게 한다 — 제안의 추론은 주지 않는다. 시범 첫 제안에서 이 패스가 **8건**을 잡았다: 들린 문의 창대 누락,
미서기문(PD) 종류, 한 부호에 창대 둘, 틀린 비고, 실명 라벨로 풀 수 있던 미결 9건.

검증자에게 줄 확인 목록:
1. 카드의 W·H(일련번호)·창대(F.L 규칙)가 일람 행과 같은가 — 카드 몇 장은 그림으로 렌더해 눈으로 본다.
   `w_consistent=false`(검토표 ★) 카드는 전부 본다 — 일련번호가 크기이고 가로 치수는 대조용이다.
2. 블록 인스턴스마다 가장 가까운 실명 라벨이 카드 실명과 맞는가(같은 블록 두 개가 다른 방이면 둘 다).
3. 종류: 부호 접두 규약 · PD · H1 > 0 문.
4. 한 부호에 창대가 둘 이상인가 → `@실명` 한정.
5. 미결 행을 실명·이름·개수로 풀 수 있는가(풀면 근거를 적는다).

불일치는 검토표에 근거와 함께 반영하고 ④ 산출물을 고친다. 그래도 남는 것은 미결 그대로 사람에게 간다.

## ⑥ xlsx → 새 프로젝트 폴더로 파싱 → 지표 → IFC

```
python $S/schedule_to_xlsx.py <작업 폴더>/decl/schedule_rows.json <작업 폴더>/decl/창호일람.xlsx   # 왕복 확인까지
python $I/parse_summary.py <층.dxf> --layer-map <lm.csv> --block-map <작업 폴더>/decl/block_map_proposal.csv \
    --schedule <작업 폴더>/decl/창호일람.xlsx --out <작업 폴더>/<이름>_decl
python ifc_builder.py <작업 폴더>/<이름>_decl.geometry.json <작업 폴더>/<이름>_decl.ifc
python $I/build_summary.py <작업 폴더>/<이름>_decl
python $I/serve_project.py <층.dxf> --folder <작업 폴더>/<이름>_decl.mep --layer-map <lm.csv> \
    --block-map <작업 폴더>/decl/block_map_proposal.csv --schedule <작업 폴더>/decl/창호일람.xlsx   # 백그라운드, URL
```

- **xlsx 는 저장소 `schedule_io` 로만.** `export_schedule_xlsx` 는 **키가 빠진** 창대에 기본값(창 900)을 채우고
  종류 칸을 subtype 에서 만든다. 그래서 일람 행은 subtype 을 늘 채우고 모르는 창대는 `null` 을 명시한다 —
  `schedule_to_xlsx` 가 다시 읽어 subtype·W·H·창대·수량이 같을 때만 성공한다.
- **새 block_map·일람이면 새 `.mep` 폴더.** 기존 폴더는 저장된 원본 설정으로 연다. 파서를 고쳤으면 떠 있는
  서버를 내리고 다시 띄운다(옛 파서 모듈을 들고 있다).
- 부호가 있는데 조인 안 된 개구부(오타·일람에 없음):
  `python -c "import json,sys;g=json.load(open(sys.argv[1],encoding='utf-8'));print(sorted({o['mark'] for o in g['elements']['opening'] if o.get('mark') and o.get('dims_source')!='schedule'}))" <이름>_decl.geometry.json`
  → `[]` 이어야 한다.

목표(전후를 나란히 보인다): 블록 개구부 `width_source=default` 는 **선언을 안 낸 블록**(주석으로 둔 미결·검토 행)만,
`dims_source=schedule` = mark 가 있는 블록 개구부 수, `openings_dims_assumed` 는 선으로 그린 창과 그 블록들만,
IFC `verified`, V106 이 늘지 않을 것. 주석으로 둔 미결 블록은 종류도 없어(`subtype` None ·
`opening_infill.skipped.subtype_unknown`) 층 높이로 뚫린다 — 눈에 띄는 것이 맞다. 사람이 정하면 사라진다.

- 시범 최종(사람 확정 뒤): 개구부 136 → 91, 블록 개구부 72개 전부 조인(가정 0), 선으로 그린 19개만 가정, 창대
  벽·인방 137개 전폭, IFC verified, V106 11 → 2.
- 시험(이 스킬의 제안 그대로, 사람 결정 둘 전): 개구부 92, 블록 73 중 조인 71 · 폭 가정 2(주석으로 둔 미결 문 ·
  검토 블록 — `width_source=default` 가 정확히 이 둘), 선 19, 창대 벽·인방 138, IFC verified, V106 4. 차이는 ④의
  미결·검토 두 행이다.

## ⑦ 검토표를 사람에게 넘긴다

`<작업 폴더>/decl/review_table.md` 를 보여 주고 **미결·검토·확신 낮음** 행을 질문으로 바꿔 묻는다(후보와 근거를 같이).
사람이 확인한 뒤에야 block_map 을 프로젝트에 쓴다. 파일은 전부 작업 폴더에 두고 저장소에 넣지 않는다.

## 하지 말 것

- block_map 에 height 적기 · 일람 행에서 sill 키 빼기(→ 900) · subtype 비우기(→ 부호 접두로 추정).
- 제안을 확인 없이 적용하기. 부호는 선언이다 — 틀린 부호는 형상이 멀쩡해 보여 검사에 안 걸린다.
- 파서가 이름으로 부호·종류를 추정하게 만들기. 이름 토큰·실명은 **제안의 근거**일 뿐, 선언은 CSV 에 사람이 쓴다.
- `mark=` 를 layer_map 에 쓰기(LayerMapError — 레이어의 개구부 전부에 같은 부호가 찍힌다).
- 기존 `.mep` 폴더에 새 block_map 을 기대하기 · 재변환 뒤 옛 `*U…` 행을 그대로 쓰기.
- 정규식 인자를 큰따옴표로 주기 · 출력을 저장소 안(저장소 루트에서 `decl/…` 상대 경로)에 쓰기.
- 스킬·코드·커밋 메시지에 고객 블록·xref·레이어 이름, 도면 번호, 현장명 쓰기(`<symbol block>` 같은 자리표시만).

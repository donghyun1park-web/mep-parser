# MEP CFD Studio

기계설비 담당자가 DXF 도면을 선택하고, 해석 구역·급배기구·발열 장비를 확인한 뒤 실내 열유동을 계산하는 로컬 웹 프로그램입니다. 복잡한 명령어나 `geometry.json` 경로를 몰라도 기본 흐름을 사용할 수 있습니다.

> 현재 계산 결과는 **초기 설계안 비교와 이상 징후 확인을 위한 스크리닝 결과**입니다. DXF에서 실제 OCC 공기영역, OpenFOAM용 watertight STL, `snappyHexMesh`, 등온·장시간 열부력 계산과 4격자 불확실성 평가까지 연결됐지만 실제 현장 DXF 3건과 사용자 UAT는 아직 통과 증거를 확보하는 중입니다. 기존 V3 결과와 새 body-fitted 결과 모두 최종 설계 승인이나 법적 성능 판정의 단독 근거로 사용하지 마세요.

## 가장 쉬운 시작 방법

1. Windows에서 `install_cfd.bat`를 한 번 더블클릭합니다. 프로젝트 전용 `.venv`를 만들므로
   시스템 Python 패키지와 충돌하지 않으며, 같은 파일을 다시 실행하면 도면·결과를 지우지 않고
   Python 실행환경만 복구합니다.
2. 실제 CFD 계산을 처음 준비할 때 `install_openfoam2606.bat`를 더블클릭합니다. WSL이나
   Ubuntu-24.04가 없으면 Windows 관리자 승인 창을 한 번 열어 자동 설치합니다. Windows가 재시작을
   요구하면 재시작 후 같은 파일을 다시 더블클릭하면 OpenFOAM v2606 설치·업데이트를 이어갑니다.
3. 설치가 끝나면 `run_cfd.bat`를 더블클릭합니다.
4. 브라우저가 열리면 **＋ 새 해석**을 누릅니다.
5. **DXF 도면 선택 · 자동 변환**에서 도면을 선택합니다.
6. 자동 인식된 해석 구역을 확인하고 방 높이, 발열량, 급배기 조건을 입력합니다.
7. **3D 모델**로 계산에 쓰일 형상을 먼저 확인한 뒤 케이스를 실행합니다.

DWG는 직접 읽지 않습니다. AutoCAD 등에서 외부참조를 바인딩하고, 단위를 확인한 뒤 AutoCAD 2010 이상 ASCII DXF로 저장해 사용하세요. 업로드 한도는 100MB입니다.

## 필요한 환경

- Python 3.11 이상
- 케이스 생성·도면 파싱: `install_cfd.bat`가 Python 라이브러리를 설치
- 실제 CFD 계산: WSL2와 WSL 안의 OpenFOAM
- Body-fitted 실제형상/3D 모드: 검증 프로필 FreeCAD 1.1.1/OCC 7.8.1

WSL/OpenFOAM이 없어도 DXF 업로드, 도면 인식, 케이스 생성과 실행 전 3D 모델 확인까지는 가능합니다. 계산 실행 버튼은 부족한 환경을 안내합니다.

스튜디오를 시작하면 기본 WSL 배포판과 다른 설치 배포판을 검사해 상세 열·부력 검증 프로필인 OpenFOAM
v2606을 우선 선택하고, 기존 v1912는 등온 계산용 legacy 프로필로만 인식합니다. `MEP_CFD_OPENFOAM_BASHRC`로
버전별 `etc/bashrc`를 명시할 수도 있습니다. Windows의 FreeCADCmd도 PATH와 표준 설치 경로에서 찾아 버전, 필수 모듈,
OCC Boolean·tessellation 스모크를 검사합니다. 대시보드의 환경 카드에서 두 실행환경을 확인하거나
**환경 다시 검사**를 누를 수 있습니다. **실제 계산 테스트**는 격리된 64셀 기준 케이스로 메시 생성,
솔버, 결과 회수와 HTML 보고서까지 확인합니다. 상세 결과는 프로젝트의
`cfd_projects/capability_manifest.json`에 함께 기록됩니다.

대시보드의 **출시 준비**는 환경, G2 4격자 검증, 실제 현장 DXF 3건, 설치·복구 수용시험,
기계설비 담당자 UAT를 각각 표시합니다. 샘플 DXF나 자체 선언은 통과 증거로 세지 않습니다. 개발자용
동일 검사는 `python release_audit.py --projects-root cfd_projects`로 실행하며 결과는
`cfd_projects/_release_evidence/release_readiness.json`과 HTML에 저장됩니다.
G2가 실행 중이면 과거 실패 결과 대신 활성 프로세스를 확인한 현재 격자와 FTT 진행률을 표시하며,
죽은 PID의 오래된 작업은 실행 중으로 표시하지 않습니다. 저장 사이에는 다음 체크포인트를 넘지 않는
예상 FTT와 실제 저장 FTT를 함께 표시해 추정값을 완료 결과로 오해하지 않게 합니다.

실제 현장 도면은 대시보드의 **현장 자동 해석**에서 확인이 끝난 DXF를 선택하면 됩니다. 프로그램이
OCC 공기영역, 안정 상세 메시, 등온 초기장, 열·부력 해석과 3.0 유동 교환시간까지 순서대로 실행합니다.
`_field_jobs/field-*/field_pipeline_job.json`에 단계와 체크포인트가 저장되므로 실패나 앱 재시작 뒤에도
**중단 지점부터 재개**할 수 있습니다. 원본 DXF나 확인본이 작업 생성 뒤 변경되면 계산 전에 중단합니다.
번들 샘플은 파일명을 바꿔도 내용 해시로 도면 선택 단계에서 비활성화되어 장시간 현장 계산을
시작하지 않습니다.
실행 중 화면은 직전 solver 비용으로 현재 FTT를 추정하되 다음 원자 체크포인트보다 앞서 표시하지 않으며,
저장이 끝나면 실제 manifest 값으로 교체됩니다.

상세 열해석이 `PASS`로 끝나면 **출시 준비 → 현장 도면 검증 등록**에서 결과를
선택하고 실제 현장 도면임을 확인합니다. 파일 경로를 입력할 필요가 없습니다. 프로그램이 원본 DXF,
`geometry.v2`, OCC 표면, OpenFOAM v2606 메시, 열해석과 VTU 결과를 다시 열고 단계별 SHA-256 연결을
확인합니다. 현장 증거는 최소 3.0 유동 교환시간, 완전한 에너지 이력과 최신 결과 시각까지 충족해야 합니다.
세 건은 파일 서명만 달라서는 부족하며, 전체 묶음에서 DXF 단위·원점·블록 회전·레이어 구성의 다양성도
각각 확인합니다. 출시 화면은 네 다양성 축을 각각 현재/2로 미리 표시합니다. 이름만 바꾼 유사 도면은
별도 현장 증거로 중복 집계하지 않으며, 번들 샘플은 파일명을 바꿔도 원본 내용 SHA-256으로
차단합니다. 이미 유효하게 등록된 원본도 후보에서 비활성화됩니다.
기존에 짧은 열해석 결과가 있다면 상세 결과 화면의 **3.0 교환시간까지 자동 계산**으로 현재 체크포인트부터 이어 계산할 수도 있으며,
브라우저를 닫아도 작업과 재개 기록이 보존됩니다. 나중에 산출물 하나라도 바뀌면 기존 증거는 자동으로
무효가 됩니다. 개발자용 수동 실행은
다음 형식이며, 일반 사용자는 화면 버튼을 사용하면 됩니다.

```powershell
.venv\Scripts\python.exe field_acceptance.py --projects-root cfd_projects `
  --source-dxf <실제.dxf> --geometry <geometry.json> --surface-dir <OCC폴더> `
  --mesh-case <메시폴더> --solver-case <열해석폴더> --actual-site
```

현장 도면 검증이 하나 이상 등록되면 **출시 준비 → 관찰 시험 시작하기**에서 기계설비 담당자 UAT를
진행할 수 있습니다. 참가자는 프로그램 실행, DXF 불러오기, 형상 확인, 조건 입력, 결과 열기, 보고서
해석의 6개 작업을 순서대로 수행하고 다른 관찰자가 성공 여부·도움 횟수·문제를 기록합니다. 시작·종료와
설정 시간은 서버가 기록하며, UAT 결과는 사용한 현장 DXF 증거의 해시와 연결됩니다. 출시 감사는 이
작업 기록에서 완료율, 설정시간 중앙값, 치명 오류 수를 다시 계산합니다. 서로 다른 담당자 3명 이상,
완료율 90% 이상, 설정시간 중앙값 15분 이하, 치명 오류 0건을 모두 충족해야 제품 준비로 인정합니다.
대소문자만 다른 참가자 코드는 같은 사람으로 처리하며 중복 집계하지 않습니다. 잘못 시작한 시험은
화면의 **시험 취소**로 진행 중 초안만 지우고 다시 시작할 수 있습니다. 이미 완료된 참가자 코드는
시험 시작 시 바로 차단해 중복 기록에 시간을 쓰지 않게 합니다. 작업 결과 버튼을 빠르게 두 번
눌러도 화면과 서버가 현재 작업 ID를 함께 확인하므로 다음 작업으로 잘못 기록되지 않습니다.
완료·취소·작업 저장도 하나의 잠금으로 순서대로 처리하고 완료 버튼은 처리 중 비활성화하므로,
여러 탭이나 빠른 중복 클릭이 최종 UAT 증거를 두 번 만들거나 초안을 중간에 지우지 않습니다.
브라우저 저장정보가 사라져도 같은 참가자·관찰자·현장 도면을 다시 입력하면 진행 중 초안을 찾아
마지막 미완료 작업부터 복구하며, 다른 관찰자나 도면으로 같은 참가자의 초안을 중복 생성하지 않습니다.

설치·복구 수용시험은 격리된 새 가상환경에서 클린 설치와 재설치를 반복하고, Windows 실행기,
OpenFOAM v2606, 현재 환경 수용시험, 실제 GCI 작업의 중단 체크포인트 재개, 기준 파일 해시 보존을
검증합니다. 출시 감사는 기록된 `PASS` 문자열을 그대로 신뢰하지 않고 기준 파일의 현재 SHA-256,
설치·재설치·재설치 후 import 확인·실행기·OpenFOAM 로그의 안전한 저장 위치와 실제 명령/성공 표식, 중단 전 체크포인트
보존 및 이후 물리시간 전진을 다시 검사합니다. 새 수용시험 결과에는 각 로그의 SHA-256도 함께
기록하며 명령 종료코드 0도 로그에 남깁니다. 개발자/target runner에서는 다음처럼 실행합니다.

```powershell
.venv\Scripts\python.exe install_acceptance.py --projects-root cfd_projects --study <gci-study-id>
```

## 결과를 읽을 때

- 초록색 수렴 표시는 잔차, 질량·에너지 수지 등 **수치 계산 기준**을 통과했다는 뜻입니다.
- 초록색 표시가 실제 도면 형상, 난류 모델, 벽체 열전달, 복사 조건까지 검증됐다는 뜻은 아닙니다.
- V3 결과 보고서에는 `다공성 복셀 스크리닝 · 설계확정용 아님` 경고가 표시됩니다.
- 중요한 의사결정은 격자 독립성 검토와 TAB/현장 온도·풍량 실측 대조를 함께 수행하세요.

## 현재 지원 범위와 다음 단계

지원하는 기본 흐름은 DXF → MEP 요소/zone 추출 → 직교 격자 OpenFOAM 케이스 → WSL 계산 → HTML 보고서/2D·3D 결과 확인입니다. 확정된 `geometry.v2`는 별도 FreeCADCmd/OCC worker에서 단일 공기 Solid와 multi-region STL로 변환되고, P3A `Allmesh`에서 no-layer `snappyHexMesh`, `checkMesh -allTopology -meshQuality`, 별도 strict 형상 진단까지 실행됩니다. 축 정렬 단일 방과 기둥·장비·원형 급배기구가 포함된 복합 기준 방 모두 OpenFOAM solver 품질 gate를 통과하며, strict zero-concavity 결과는 차단 조건이 아닌 진단 경고로 보존됩니다.

P3B는 `빠른 메시`와 `안정 상세 메시`를 분리합니다. OpenFOAM v1912에서 level 3 전이와 벽·장비 prism layer가 급·배기구 및 장비 모서리의 압력 발산을 만들었으므로, 기본 상세 프리셋은 전역 0.35 m 배경과 level 2 표면을 사용하고 prism layer를 끕니다. G2 기준 방은 20,377셀에서 무유동·급기·중력·800 W 열원 4단계가 모두 0.002초를 통과했습니다. 경계층 설정은 수동 실험값으로만 남기며 기본 UI에는 노출하지 않습니다.

P4 기반은 상세 메시에서 급·배기 설계풍량을 실제 경계조건으로 변환해 `simpleFoam`을 실행하고, 선형·비선형 잔차 이력, continuity, y+ 벽처리 분기를 `run_manifest.v1`에 기록합니다. 500/500 CMH 실제 파일럿은 global continuity `3.47e-8`, 점성층 87.66%, 전이영역 12.34%, 벽처리 유효면적 87.66%로 벽처리 80% 기준을 통과했습니다. 다만 600회에도 속도·압력 정상상태 잔차가 진동해 결과는 `WARN`, `design_ready=false`입니다.

정상상태 수렴 미달 결과에는 **시간변동 진단 계속** 버튼이 표시됩니다. 마지막 정상상태 time에서 `pimpleFoam`을 안전하게 재시작하고 Courant, 새 U 스냅샷 3개의 평균·RMS 유속 변동폭, 방 체적/급기유량 기반 유동 교환시간 확보율을 계산합니다. 기본 10초 진단은 원인 분류용이며 최소 유동 교환시간을 채우지 않으면 결과가 안정적으로 보여도 설계 검토 `PASS`로 승격하지 않습니다.

이전 60,644셀·prism layer 상세 transient 벤치마크는 등온 유동에서는 1시간 예산 gate를 통과했지만 열·부력에서는 불안정해 기본 프리셋에서 제외했습니다. 현재 20,377셀 안정 상세 프리셋은 OpenFOAM v2606에서 quick 정상장 보간과 bounded upwind를 사용해 0.05초 열·부력 gate와 0.25 유동 교환시간 장시간 수용시험을 통과했습니다. 4격자 GCI용 3.0 유동 교환시간 검증은 별도 작업으로 실행하며, 실행별 누적 물리시간·실제시간·순수 solver 시간·WSL 준비/회수 고정비·남은 예상시간은 `thermal_progress.json`에 보존됩니다.

0.05초 상세 안정성 시험에서 시작해 최소 0.25 유동 교환시간까지 이어지는 장시간 해석, 비정형 후처리, 검증 보고서와 중단 후 재시작을 연결했습니다.

장비 발열·부력 백엔드 1차 계약을 구현했습니다. `geometry.v2`의 장비 kW와 대류분율을 OCC 노출면 patch까지 추적하고, 적용 대류열과 계산에서 제외한 복사열을 분리 기록합니다. 장비 인접 유체 cellZone 열원, `buoyantBoussinesqPimpleFoam`, 최고온도·Boussinesq ΔT·Courant·배기온도 기반 에너지 폐합 gate도 생성됩니다. v1912에서는 안정 상세 메시가 0.002초 매트릭스까지만 통과하고 0.05초에서 최대 Courant 3.574와 압력 FPE로 중단됐습니다. 같은 20,377셀·500/500 CMH·800 W 케이스를 v2606에서 quick 정상장 `mapFields` 보간과 모든 대류항의 `bounded Gauss upwind`로 실행한 결과 0.05초 정상 종료, 전체 최대 Courant 0.0152, 최종 온도 293.150~293.309 K를 기록했습니다. Studio에는 완료된 상세 등온 결과 뒤에 **열·부력 안정성 시험 (0.05초)** 버튼이 표시되며, 장시간 설계 결과가 아님을 함께 안내합니다.

열·부력 결과는 마지막 time에서 안전하게 이어갈 수 있습니다. 재시작 때 장비 patch 기반 열원 cellZone을 다시 만들기 때문에 전체 polyMesh를 Windows로 반복 회수하지 않습니다. 로컬에는 시간창 통계를 위해 최근 결과를 보존하지만, WSL 재시작 작업공간에는 입력·`0`·최신 체크포인트만 선별 복사해 이전 시간 폴더를 복사했다가 삭제하는 I/O를 피합니다. Windows 회수 전 관리 프로세스가 비정상 종료돼도 동일 입력 지문을 가진 WSL 작업공간의 더 최신 time을 발견하면 삭제하지 않고 이어서 계산합니다. 재개 준비 때마다 달라지는 감사 시각은 지문에서 제외하지만 물리·수치 설정과 주요 필드는 계속 검증합니다. 같은 디렉터리에서 solver가 아직 실행 중이면 지문과 무관하게 중복 재개를 거부합니다. 입력 지문이 다른 WSL 공간에 Windows보다 최신 time이 남아 있거나 상태 조회가 시간 안에 끝나지 않으면 자동 재복사·삭제를 금지하고 안전 오류로 중단합니다. 안정성 시험은 최대 시간간격 0.0005초를 유지하고, 통과 후 continuation은 v2606 bounded 프로필(기본 최대 시간간격 0.02초)을 사용합니다. 첫 continuation은 안정성 시험 비용을 시간간격 차이로 보수 환산하고, 이후에는 실측 solver 속도를 사용해 기본 30분 벽시계 예산 안에서 다음 체크포인트 길이를 자동 축소합니다. 이 조절은 저장·복구 단위만 바꾸며 물리시간 목표나 판정 기준은 바꾸지 않습니다. 107,991셀 fine 실제 시험에서 최대 Courant 1.015로 2.0 gate를 통과했습니다. `thermal_progress.json`에는 누적 물리시간, 유동 교환시간 확보율, 실제 사용한 수치 프로필, solver 초/물리초, 준비·회수 고정비와 예상시간이 기록됩니다. 배기 에너지 항은 저장된 `inletValue`가 아니라 실제 양(+)의 `phi`로 가중한 인접 내부 셀 온도를 사용하며, 유동 교환시간 전의 낮은 배기 회수율은 실내 축열 중인 과도상태로 표시합니다.
각 청크 회수는 실행 전체의 처음·중간 감사 기준점과 최신 연속 스냅샷을 최대 7개 가져오고,
Windows에는 최신 28개를 유지해 마지막 0.1 FTT 정상성 시간창이 최소 표본 수를 잃지 않게 합니다.

G2 장시간 수용시험은 물리시간 59.2236초, 유동 교환시간 확보율 25.00%에서 `PASS`했습니다. 최대 Courant는 0.305, 온도 범위는 293.150~306.099 K였습니다. 누적 투입열 47,378.88 J에 대해 OpenFOAM 셀 체적 기반 실내 축열 39,707.06 J와 실제 유출 `phi` 적분 배기열 7,675.47 J를 합산한 과도 에너지 폐합률은 100.0077%였습니다. 잔여 계산시간이 저장 간격보다 짧으면 `writeInterval`을 자동 축소하며, 셀 체적은 최초 생성 후 재시작 time으로 복사해 반복 후처리 비용을 줄입니다.

상세 결과가 생성되면 Studio의 **2D·3D 단면 보기**에서 X/Y/Z 중앙 단면의 온도·속도를 전환하고, 세 단면을 한 화면의 3D 투영으로 확인할 수 있습니다. 모든 데이터와 렌더링 코드는 로컬에 있어 인터넷 연결이 필요 없습니다.

대시보드의 **메시 불확실성**에서는 경로를 입력하지 않고 GCI 준비 확인이 끝난 도면을 이름으로 선택합니다. 단일 확인 방, 급기구, 배기구, 발열원이 있어야 하며 총 급·배기 설계풍량 차이는 1% 이하여야 합니다. 미충족 도면은 비활성화되고 방 확인·천장 높이·풍량·누락 설비 등 차단 사유와 **이 도면 확인하기** 링크를 한국어로 안내합니다. 링크를 열어 방과 천장 높이, 급·배기구별 CMH, 발열 장비 위치·kW를 입력하고 **정밀 3D 입력 확인·저장**을 누르면 원본은 그대로 두고 `*.confirmed.geometry.json` 확인본을 만듭니다. 확인본은 즉시 GCI 후보가 됩니다. 직접 경로는 고급 항목에만 남기고 실행 직전에 같은 의미 검사를 다시 수행하므로 미확인 파일로 우회할 수 없습니다. 동일한 CAD·유량·열원·부력 조건과 물리시간으로 완료된 결과 4개에 `grid_convergence.v3`를 계산하고, 실제 공기 체적과 셀 수로 유효 격자폭을 구합니다. 마지막 0.1 유동 교환시간의 체적가중 평균온도·온도 p95·유속 p95에 Eça–Hoekstra(2014) 최소제곱 절차를 적용하며, 각 지표의 메시 불확실성 5% 이하와 시간창 변화 2% 이하를 모두 만족해야 `PASS`입니다. 기존 3격자 v2 GCI도 직접 비교 호환용으로 유지됩니다.

장시간 GCI가 중단된 경우 기존 작업 ID를 지정해 마지막 완전 체크포인트부터 재개할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe run_gci_acceptance.py --root cfd_projects --study gci-0123456789ab
```

작업이 성공 또는 실패로 끝나면 현재 G2 결과를 포함한 `release_readiness.json`과 HTML도 자동으로
다시 생성합니다. 릴리스 감사 생성 오류는 계산 결과를 덮어쓰지 않고 별도 진행 이벤트로 남깁니다.

Studio·CLI·복구 실행기는 작업별 `gci_job.lock`과 워크스테이션 공용 `_system/cfd_solver.lock`을 함께 확인합니다. 같은 작업뿐 아니라 서로 다른 GCI·현장 DXF 작업도 OpenFOAM을 동시에 실행하지 않습니다. 실행 중이면 PID와 함께 재개를 거부하며, 비정상 종료로 소유 PID가 사라진 잠금은 다음 실행에서 자동 회수됩니다. 메시·등온·열 solver가 오래 실행되는 동안에는 최신 진행 문구와 생존 시각을 작업 파일에 5초 간격으로 기록해 대시보드에 표시합니다. 하트비트 갱신시각과 단계 시작시각은 분리되어 있어 최신 문구가 계속 바뀌어도 다음 체크포인트 예상 진행이 되돌아가지 않습니다. Windows에서는 GCI·현장 자동 해석이 solver 잠금을 보유한 동안 시스템 자동 절전만 억제하고, 작업 종료나 예외 뒤 즉시 원상 복구합니다. 화면 꺼짐 설정은 바꾸지 않습니다. 따라서 작업 관리자의 Python/OpenFOAM 프로세스를 강제로 중복 실행하지 마세요.

실행 중인 열유동 청크는 마지막 저장값과 별도로 **예상 진행 시각·FTT·다음 저장 시각**을 표시합니다.
이 값은 직전 solver 성능과 경과시간으로 계산하고 다음 원자 체크포인트를 넘지 않게 제한하므로,
진행 확인용으로만 사용하며 저장된 해석 결과로 오해하지 않습니다.
비숙련 사용자도 종료 시점을 판단할 수 있도록 전체 목표까지의 **남은 실제시간**과 컴퓨터 현지시각 기준
**완료 예상 시각**도 함께 표시하며, 성능 표본이 없거나 유효하지 않으면 임의 시각을 만들지 않습니다.

**자동 4수준 계산**에 geometry.json 경로를 넣으면 매우 거친·거친·중간·세분 메시부터 등온 초기장, 최소 3.0 유동 교환시간 열·부력 계산과 불확실성 보고서까지 대기열에서 실행됩니다. 작은 급·배기구는 매우 거친 격자에서도 면적오차 5% 이내를 지키도록 그 수준에만 최소 국부 해상도를 적용합니다. 호환되는 완료 또는 짧은 결과는 검증 후 재사용·복제해 이어 계산합니다. OpenFOAM 계산은 서로 겹치지 않으며 `_body_gci/gci-*/gci_job.json`에 단계별 상태가 저장됩니다.

각 열·부력 실행이 끝나면 최신 time을 ASCII VTU로 내보내고 `cfd_post.py`가 cell 중심좌표로 결과를 읽습니다. `result_manifest.json`에는 원본 VTU·mesh·run 해시, 필드 위치와 단위가 기록되며, `results/body_fitted_summary.json`에는 온도·속도 통계와 최고값 좌표가 저장됩니다. `results/slices/`에는 대표 셀 길이 절반 폭으로 선택한 x/y/z 중앙 단면 JSON이 생성됩니다. Studio의 **상세 결과 리포트**는 이 비정형 데이터만 사용하며 구조격자 셀 순서를 추측하지 않습니다.

구현 순서와 각 단계의 통과 기준은 [NEXT_PHASE_PLAN.md](NEXT_PHASE_PLAN.md)에 정리했습니다.

상세 사용법과 검증 기준은 [CFD_사용설명서.md](CFD_사용설명서.md)를 참고하세요.

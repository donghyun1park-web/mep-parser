# 프로젝트 수정 보존과 IFC 검증

이 기능의 완료 범위는 **수정이 보존되고 검증 근거를 확인할 수 있는 검토용 3D·IFC**다. DXF 해석의 완전한 정확성, 물량 보증, 설계·시공 적합 판정을 뜻하지 않는다.

## 원본 도면과 3D 검토

GUI에서 미리보기를 열면 ‘도면 + 3D’ 화면이 기본으로 열린다. 회색 선은 입력 DXF, 파란 선은 해석한 부재다. 파란 선이나 3D 부재를 선택하면 같은 EID가 강조된다. 다층 프로젝트는 도면 쪽 층 선택으로 각 원본을 확인한다. 검토 대기 목록의 항목을 누르면 해당 부재로 이동한다. 항목 선택만으로 검토 완료가 되지는 않는다.

‘수평 단면’의 높이는 모델의 절대 Z 좌표(mm)다. 위쪽 숨기기는 화면 표시만 바꾸며 프로젝트 수정 번호나 IFC 기하를 바꾸지 않는다. 선택한 부재가 숨겨져 있으면 검토 이동 시 숨기기를 해제한다. 단면의 절삭면을 메우거나 CAD 절단 객체를 만들지는 않는다.

원본 표시에서 텍스트·해치 등 미지원 요소와 도형 표시 제한으로 생략된 내용을 안내한다. 원본 데이터가 없거나 읽기 실패한 경우에도 3D 검토는 가능하다. 원본 표시용 선은 IFC 생성·검증 입력에 포함하지 않는다.

화면 개발 소스는 `frontend/src`, 배포 자산은 `frontend/built`다. 개발자는 Node.js가 설치된 환경에서 `cd frontend`, `npm ci`, `npm run dev`를 사용한다. 개발 서버의 첫 화면은 별도로 표시된 샘플이며 실제 프로젝트 수정 서버가 아니다. 변경 후 `npm run build`와 `npm test`를 실행한다. Python GUI·독립 HTML·패키지 실행에는 Node.js나 개발 서버가 필요 없다. `MEP_PYTHON` 환경 변수로 개발 서버가 규약을 읽을 Python 실행 파일을 지정할 수 있다.

## GUI 사용 순서

1. `run_gui.bat`를 실행하고 DXF와 레이어/블록 매핑을 선택한 뒤 Parse를 누른다.
2. 기본 저장 위치는 도면 옆 `<도면명>.mep` 폴더다. 그 위치에 쓸 수 없으면 GUI가 저장 폴더 선택을 연다. 기존 프로젝트는 **프로젝트 열기**로 연다.
3. **3D 미리보기**를 열어 치수, 삭제, 추가, 이동, 분할, 결합을 편집한다. Python GUI를 열어 둔 동안 브라우저가 같은 프로젝트 저장 서비스에 연결된다.
4. **서버에 저장됨**은 디스크 저장 응답을 받은 상태다. 저장 중·미저장·충돌 상태에서는 저장 완료로 간주하지 않는다. 연결 실패 시 재시도하거나 수정 파일을 내려받아 보관한다.
5. 다시 Parse하거나 FreeCAD 빌드를 실행하면 저장된 최신 revision을 읽는다. 오래 열린 창의 저장 요청은 충돌로 거절되며 최신 수정을 덮어쓰지 않는다.
6. 기본 출력은 **FreeCAD 빌드**다. 로그와 `<출력명>.build.json`에서 FCStd와 IFC 각각의 상태 및 실패 원인을 확인한다.

## 저장 내용과 복구

| 파일/폴더 | 내용 |
|---|---|
| `project.json` | 프로젝트 ID, 수정 번호, 입력·매핑·일람표 경로와 지문, 층 정보, 층별 수정, 재연결·폐기 결정 |
| `project.previous.json` | 직전 정상 저장본 |
| `imports/` | 가져온 이전 수정 파일의 원본 사본 |
| `builds/geometry-r*.json` | 빌드가 읽은 수정 번호의 변경되지 않는 입력 사본 |
| `geometry.json` | GUI용 파생 결과. 수정의 원본 저장소는 `project.json`이다. |

프로젝트는 입력 도면과 설정 파일을 **경로로 연결**한다. 프로젝트 폴더만 다른 PC로 복사하면 원본 도면까지 따라가지 않는다. 현재 단계에는 도면 패키징/이동 마법사가 없다.

저장은 임시 파일 쓰기·flush/fsync·교체 순서로 진행하고 직전 정상본을 보존한다. 손상된 프로젝트를 열면 GUI에서 이전 정상본 복구를 선택할 수 있다. 손상된 파일도 별도 사본으로 보존한다. 두 창/두 프로세스가 동시에 저장해도 파일 잠금과 기준 revision 검사로 덮어쓰기를 차단한다.

브라우저의 미저장 사본은 프로젝트 ID와 기준 revision에 연결된다. 충돌 때 최신 데이터를 읽어 덮어쓰는 대신 미저장 내용을 내보내고 최신 프로젝트를 확인한다. GUI 종료 시 PC 내부 연결도 닫힌다. 독립 HTML 파일은 서버 자동 저장 기능 없이 내보내기를 사용한다.

## 도면 변경과 검토

EID가 유일하게 일치하는 수정만 재적용한다. 사라지거나 중복된 EID는 자동으로 다른 부재에 붙이지 않는다. 연결이 끊긴 수정은 같은 층·종류에서 거리, 방향, 겹치는 구간을 비교한 최대 5개 후보와 이전 위치를 보여준다. 연결 또는 폐기는 명시적으로 선택하며, 보류하면 미해결 상태로 남는다. 후보 동점은 EID 순서로 정렬한다.

다층 프로젝트는 각 층의 원본 좌표와 로컬 EID로 수정 사항을 저장하고, 화면/IFC에 전달할 때 층 접두사와 offset/z를 적용한다. 입력의 `align`은 먼저 해결한 명시적 offset이어야 한다. 층 높이는 기본값이며 사용자가 해당 부재에 지정한 높이가 우선한다.

검토 완료는 당시의 형상, 관련 치수와 진단에 연결된다. 폭만 수정했다고 다른 검토 사유가 자동 해제되지 않는다. 관련 내용이 바뀌면 다시 검토 대상으로 표시한다. 이전 수정 파일의 지문 없는 `review_resolved`도 다시 확인해야 한다.

이동은 꺾인 벽의 모든 정점을 보존한다. 분할은 선택한 실제 선분에서 하고, 결합은 같은 층·직선상·동일 치수와 속성의 벽에 한한다. 스냅에는 화면 거리와 실제 거리 한계를 함께 적용한다. 접합 틈·겹침·개구부 연결 오류는 표시하며 자동으로 좌표를 고치지 않는다.

## 산출물 상태 읽기

| 상태 | 의미 |
|---|---|
| `verified` | 현재 입력·실행과 파일 해시가 일치하고 해당 산출물 검사를 통과 |
| `failed` | 생성·저장·필수 검사 중 실패. 보고서의 원인을 확인 |
| `diagnostic_nonverified` | 오류를 허용해 만든 진단 결과. 검증 완료 IFC로 사용하지 않음 |

빌드 전에 기하 검사를 실행한다. FCStd는 별도 경로에서 다시 열고 재계산해 형상·절삭·QA 속성이 보존되는지 확인한다. IFC도 다시 열어 모든 모델 대상 EID의 대응, 객체 형상, 층과 QA 속성을 확인한다. 한 원본이 여러 객체로 분할되거나 여러 원본이 한 벽에 합쳐져도 `eid_map`과 `SourceEIDs`에 대응을 남긴다. 개구부는 실제 절삭한 벽과 생성된 문·창문 객체의 GlobalId까지 추적한다.

FreeCAD 형상과 IFC 체적 오차의 기본 허용치는 `max(1 mm³, 체적의 0.5%)`다. 절삭한 벽은 작은 개구부 누락도 검출하도록 해당 벽의 체적과 절삭량 중 작은 값을 기준으로 제한한다. 세계 좌표에서 형상의 경계값도 1 mm 이내인지 대조한다. 실제 적용한 허용치와 결과는 보고서에 기록한다.

파일이 이미 있거나 프로세스 종료 코드가 0이라는 이유만으로 성공하지 않는다. 실행 ID, 입력 해시, 실제 파일 해시가 맞아야 한다. 누락된 부재, 미해결 고아/충돌, 검증 모듈 실패는 차단 사유다. 강제 실행 결과는 별도 진단 파일명과 상태를 사용한다.

간편 IFC 빌더도 공통 치수 규약과 검증을 사용한다. 지원하지 않는 요소가 있으면 생성 전에 카테고리 목록을 반환하고 FreeCAD 사용을 안내한다. 기존 BOQ와 4D 도구는 남아 있지만 이번 개선의 보증 범위에 포함되지 않는다.

## 개발·검증

전체 테스트는 `python -B -m pytest -q -p no:cacheprovider`로 실행한다. `python tests/run_all.py`는 pytest fixture가 필요한 검사와 설치되지 않은 선택 도구를 **미실행**으로 따로 집계한다. 실제 FreeCAD 검사와 실무 도면 회귀 검사가 실행됐는지 최종 결과와 로그를 함께 확인한다. 실무 도면 경로는 기존의 `tests/golden.local.json`에서 지정하며, 회귀 요약 일치는 해석 정확성 전체의 보증이 아니다.

PC 내부 HTTP 연결은 `127.0.0.1`에만 열며 세션 토큰, Host와 Origin 검사로 제한한다. HTTP 수정 요청은 대상 EID와 프로젝트 ID·기준 수정 번호를 사용하고 임의 파일 경로를 받지 않는다. GUI와 MCP도 같은 프로젝트 저장 처리를 사용한다.

# 도면 기하를 보존하는 환기·난방 모델링

이 문서는 참조 현장의 단위세대 환기·난방 검토 모델에서 확인한 기술을 프로그램으로 옮기는 기준이다. 원도면의 좌표와 설비 분류, 설치 높이, 제품 치수, 표시용 가정을 구분한다. 실제 현장 도면마다 레이어 이름과 기호가 다르므로 참조 현장의 핸들·좌표·규격을 일반 규칙으로 사용하지 않는다.

## 처리 구조와 Codex의 역할

`DXF → 프로젝트 프로파일 → 결정론적 추출 → geometry.json → 검토·수정 → 결정론적 빌더 → 저장 파일 재검사` 순서다. 기존 FreeCAD/IFC 출력은 유지하고 Blender/GLB를 추가 검토 출력으로 사용한다.

Codex는 레이어·기호 분류 후보, 누락 진단, 원문 표기 해석과 검토 제안을 돕는다. 좌표를 상상해서 채우거나 임의 연결을 승인하지 않는다. 제안에는 원본 해시, 대상 EID/출처, 변경할 필드, 근거가 필요하다. 수정은 프로젝트에 저장하고 다음 추출에도 유지한다. 원본 변경으로 대상이 사라지면 자동으로 다른 객체에 붙이지 않고 재연결 대상으로 남긴다.

## 환기 도면에서 옮긴 기술

1. 원도면의 명시 중심선과 외곽선을 구분한다. 평행 경계의 법선 방향 간격과 투영 겹침 길이는 실제 폭의 근거가 된다. 색상 하나만으로 중심선이나 계통을 확정하지 않는다.
2. 양면선과 곡선 부속을 현오차 제한으로 분해한 뒤 정밀도 격자·선 합집합·polygonize로 외곽 후보를 만든다. 경계에 기여한 원본 핸들을 남긴다. 닫히지 않은 경계, 기호와 해치가 섞인 후보는 진단 대상이다.
3. 경계 외곽은 `geometry_mode=footprint`로 높이 압출한다. 명시 경로는 연속 중심선 스윕으로 만든다. 부속의 실제 평면 외곽과 임의 상자 연결을 혼동하지 않는다.
4. 디퓨저 본체·방향 심벌이 한 위치에 두 개의 INSERT로 나타날 수 있다. 블록 개수와 실제 기구 개수는 별도 검토한다. 기호 외곽 크기는 제조사 제품 크기의 증거가 아니다.
5. 덕트 상단 부착 조건은 층간 높이와 상부 슬래브 두께로 계산한다. 평면 교차부에 높이 단차 근거가 없으면 임의로 한 덕트를 낮추지 않고 간섭 검토를 남긴다.

## 난방 도면에서 옮긴 기술

LINE 길이는 끝점 거리, ARC 길이는 반지름×회전각, LWPOLYLINE bulge는 원호로 분석한다. 분석 길이와 렌더링용 샘플 길이를 별도로 저장한다. 원호를 작은 직선으로 바꾸는 최대 현오차도 프로젝트 기록에 포함한다.

폴리라인의 음수 bulge를 가상 ARC로 분해하면 호 방향이 원래 꼭짓점 순서와 다를 수 있다. 원래 순서로 되돌린 후 연결한다. 끝점 그래프는 수치적으로 같은 원본 끝점만 연결하고, 평면상의 교차는 자동 접속점으로 보지 않는다. 열린 경로·분기점·가까운 끝점은 따로 기록한다.

참조 현장 원본에는 상단 4회로와 하단 6회로가 따로 있었고, 상단 한 회로에 약 4.17mm의 실제 단절이 있었다. 모델은 이 단절을 열어 두었다. 따라서 연결된 경로 수와 해석된 회로 수는 같지 않을 수 있다. 원본 경로 길이에는 표시용 수직 연결관이나 헤더 길이를 몰래 더하지 않는다.

PB 호칭 15A와 외경 15mm는 같은 정보가 아니다. 외경·내경·관벽 두께·제품 규격을 구분한다. 모델에서 사용하는 외경은 도면·제조사 사양·사용자 입력·가정 중 어느 근거인지 기록한다.

## 좌표와 설치 높이

`geometry.json`의 물리 좌표 단위는 mm다. DXF 단위 정규화는 파서가 담당하고, Blender 준비 단계는 mm 입력만 받는다. 도면 좌표가 크더라도 원본을 바꾸지 않고 범위 중심을 표시 원점으로 별도 저장한다. Blender 좌표는 `(source_mm - origin_mm) / 1000`이다.

Z 범위는 `geom_contract.z_range()` 하나를 따른다. pipe/duct/tray의 elevation은 축, slab/beam의 z_base는 상단, wall/column의 z_base는 하단이다. 원래 2D 기호에 포함된 큰 Z값을 설치 높이로 오인하지 않는다.

바닥 구성은 프로파일의 `floor_layers[{role, thickness_mm}]`에 둔다. 지원 역할은 `impact_insulation`, `foamed_concrete`, `screed`다. 각 층은 실제 닫힌 source slab의 상단을 기준으로 누적한다. 프로파일의 높이 기준은 `levels.structural_slab_top_mm`로 파서와 합의한다. 독립된 두 번째 datum를 만들지 않는다.

source slab 외곽이 없으면 `floor_footprint_not_available` 진단을 표시하고 배관 bbox를 건축 바닥으로 만들지 않는다. 바닥층은 외곽 검토용이며 젖은 구역 단차·방수·구배·관통이나 모르타르에서 배관 체적을 빼는 상세 계산을 포함하지 않는다.

두 도면의 정합은 기준선·블록·해치 같은 독립 근거로 확인한다. 변환행렬과 잔차를 남기고, 이동·회전·축척을 분류 규칙으로 하드코딩하지 않는다. 정합할 기준점이 없는 다른 배치를 기존 건물 안에 억지로 맞추지 않는다.

## 메시와 편집 파일

- 호스트 Python에서 Shapely 2.1 이상으로 메시 payload를 준비한다. Blender의 Python에 Shapely를 별도로 설치할 필요가 없다. constrained Delaunay 지원이 없으면 준비 단계가 명시적으로 실패한다.
- Polygon 외곽·구멍의 감김을 정규화하고 constrained Delaunay로 상·하면을 만든다. 공선 꼭짓점을 임의 삭제하지 않고 모든 ring의 측면과 대응시킨다. 모든 모서리가 두 면에 사용되는지와 방향·체적을 검사한다.
- 난방관은 편집 가능한 Blender Curve다. 직경을 화면상 잘 보이게 부풀리지 않는다. 짝수 bevel resolution을 사용하고 평가된 실제 메시의 상·하단을 다시 측정한다.
- 사각 경로는 수평 평면에서 miter를 갖는 연속 외곽을 만든 뒤 높이 압출한다. 수직·경사 덕트, 제작용 피팅, 내부 유체 공간이나 판 두께를 구현한 모델은 아니다.
- 기본 `MEP_EXPOSED` 장면에서는 최상부 바닥층을 숨겨 배관을 검토하고, `MEP_COVERED`에서 모든 바닥층을 확인한다. 원본 없는 건축·장비·플렉시블을 추가 생성하지 않는다.
- zone과 opening은 독립 물리 솔리드로 만들지 않고 입력과 진단에 보존한다. 임의 Boolean 벽체 타공은 수행하지 않는다.

## 파일 검증과 실행 영수증

GUI 연동 API는 다음과 같다.

```python
from blender_runner import build_blender
receipt = build_blender(geometry_path, out_dir, blender_path=None, timeout=900)
```

반환 status는 `verified`, `failed`, `blocked`다. 먼저 `verify_geometry()`로 입력·프로파일·수정 충돌을 검사하고 오류가 있으면 네이티브 실행 전에 중단한다. 경고는 영수증에 보존한다. 네이티브 프로그램 미발견 또는 자원 미달은 `blocked`이며 성공이 아니다. `artifacts`는 실제 저장·재검사를 통과했을 때만 채운다. run별 폴더를 새로 만들어 이전 파일을 현재 성공의 증거로 재사용하지 않는다. 입력 바이트를 한 번 읽어 해시와 `input_geometry.json` 스냅샷을 만들고 이 동일 바이트에서 payload를 준비한다. Windows subprocess는 보이지 않는 창으로 실행한다. 실행 전 여유 RAM·디스크를 측정하고 최소 1GiB와 기하 크기를 고려한 작업 예상치에 미달하면 시작하지 않는다.

검사는 다음 근거를 대조한다.

1. 입력 geometry·payload·실행 ID와 저장된 scene/object의 해시.
2. 실제 `.blend` 재열기, 전체 EID와 원본 참조, 모든 Curve 제어점·반지름·평가 메시 Z, 준비된 메시 꼭짓점·면.
3. GLB의 단일 기본 활성 장면, 장면에서 도달 가능한 실제 geometry node, source EID·참조·입력 해시, 고아 메시 부재.
4. GLB BIN의 실제 POSITION 데이터와 부모 변환으로 계산한 크기·위치. glTF Y-up 변환을 적용하여 Blender 실제 평가 메시와 대조한다.
5. 반환 직전 원본 입력 해시를 다시 확인하여 실행 중 수정된 입력으로 낡은 출력을 승인하지 않는다.

`use_selection=True`만으로는 다중 장면 내보내기 오류를 막지 못한다. exporter에 `use_active_scene=True`도 지정하고, 검증기는 기본 장면의 실제 노드 도달성까지 확인한다. 파일 존재, 객체 개수, stdout PASS 문자열만으로 출력 성공을 판정하지 않는다.

이 검증은 도면 기하·교환 파일의 무결성에 대한 것이다. 유량·풍량·압력손실·열부하·소음·시공 적합성 검증은 별도이며 `verified`를 설계 승인으로 표시하지 않는다.

## 다른 현장용 회귀 자료

현재 실제 환기 회귀 자료는 이전에 사람과 Codex가 상세 검토하여 만든 참조 현장 전체 환기 모델과 범위가 다르다. `outputs/sample-validation/<현장>_ventilation/source-validation.json`은 SA/RA의 빨간 명시 중심선 45개를 일치 끝점 기준 41개 경로, 67.457129411m로 추출한 검사다. 이 예제의 110×54mm 일괄 단면은 임시 가정이며 전체 환기 시스템의 실제 규격을 확정한 결과가 아니다.

`outline-review-validation.json`의 여러 레이어 외곽선 시험은 리브·기호가 포함된 닫힌 면 후보 2,911개를 복원한다. 선택 원본 5,152개 중 완전 표현 2,425개, 열린 경계·부분 경계·미지원 2,727개가 남으므로 커버리지는 미완료다. 이를 완성 덕트·피팅 개수나 누락 없는 모델로 표시하지 않는다.

혼재된 110×54/204×60 사각 구간, 100~125 원형 구간, 기구·부속·장비의 분류는 프로젝트 프로파일과 Codex/사용자 검토가 더 필요하다. 현재 지원은 검토 가능한 결정론적 추출과 재현 출력이며, 모든 DXF를 자동으로 정확히 완성한다는 뜻이 아니다.

원본 고객 도면은 허가 없이 배포하지 않고 다음 변환을 적용한 작은 합성 DXF를 함께 사용한다.

| 변환 또는 결함 | 기대 결과 |
|---|---|
| 레이어·블록 이름 및 BYLAYER 색 변경 | 프로파일 매핑 후 같은 물리 기하; 미확정 분류는 검토 대상 |
| 임의 이동·23도 회전·큰 WCS | 길이·외경·높이 불변, 역변환 좌표 일치 |
| mm/m/inch 변환과 단위 미지정 | 확정 단위에서는 물리 길이 불변; 미지정은 확인 필요 |
| 선 방향·엔티티 순서·양음 bulge 변경 | 동일 경로와 분석 길이, 원본 출처 유지 |
| INSERT 회전·중첩·반전 | WCS 기하·인스턴스 출처 유지; 비균일 확대 원호는 별도 지원 판단 |
| 한 파일의 여러 대안 배치 | 현재 선택 배치만 모델·수량에 포함 |
| 단절·교차·T분기·겹친 선 | 자동 연결로 원본 회로를 바꾸지 않고 진단 |
| 외경·덕트 높이·바닥 두께 누락 | 프로젝트 기본값과 사용자 확정값 구분 |
| 기호 쌍·제어선·문자 노이즈 | 심벌 중복 수량·가짜 덕트 예방 |
| 구멍·공선 경계·잘린 캡 | 외곽·체적·닫힌 메시 검사에서 결함 탐지 |
| GLB의 잘못된 기본 장면·부모 이동 | 실제 장면/BIN 검사에서 실패 |
| 원본 개정·EID 삭제·분할 | 사용자 수정 보존 또는 명시 재연결 검토 |

현재 단위 테스트는 `tests/test_blender_export.py`이며 네이티브 앱을 실행하지 않는다. 네이티브 결과는 실행별 `native_verification.json`과 `blender_build.json`으로 별도 확인한다. 합성 fixture, 변형 fixture, 특정 현장 검증을 서로 구분해 기록한다.

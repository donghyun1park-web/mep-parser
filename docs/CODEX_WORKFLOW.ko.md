# 환기·난방 DXF 모델링과 Codex 협업

프로그램이 원본 좌표와 곡선을 계산하고, Codex가 도면 분류·설정 제안·누락 설명을 맡습니다. 설정과 수정은 프로젝트에 저장됩니다. 별도 AI API 키 없이 로컬 MCP 서버를 Codex에서 호출할 수 있습니다. 기존 선택적 Claude 자동분류 기능은 별도 기능입니다.

## 현장 사용 순서

1. `run_gui.bat`를 실행하고 DXF를 엽니다. 기존 프로젝트는 다시 열어 수정 이력을 유지합니다.
2. **도면 단위 확인**에서 헤더 단위·원본 선 길이·치수 주석을 비교합니다. 알고 있는 원본 길이와 실제 mm 길이로 배율을 계산한 뒤 **단위 저장 · 다시 모델링**을 누릅니다. 건축 도면에도 사용할 수 있습니다. 이후 **설비 도면 설정 · Codex 제안**에서 모델링 영역과 레이어를 선택합니다. 한 장에 서로 다른 평면이 있다면 각각 영역을 지정합니다. 단위 미지정 DXF는 실제 도면 단위를 입력합니다.
3. 난방 중심선은 `pipe / centerline`, 환기 중심선은 `duct / centerline`, 닫힌 덕트 외곽은 `duct / outline`을 선택합니다. 배관은 실제 외경, 중심선 덕트는 폭·높이, 외곽 덕트는 높이를 입력합니다. 호칭 규격과 실제 치수는 별도 칸입니다.
4. 설치 기준을 선택합니다. `slab_soffit`은 상부 슬라브 하단에 덕트 윗면을 맞춥니다. `foam_top`은 바닥 슬라브 상단에서 차음재·기포층을 쌓은 위치에 배관 아랫면을 맞춥니다. 층간 높이와 슬라브 두께, 각 바닥층 두께는 현장 조건을 입력합니다.
5. **설정 저장 · 다시 모델링**으로 저장합니다. 3D 원본 겹쳐보기에서 경로와 외경, 영역을 확인하고 검토 항목을 수정합니다. 화면의 수정은 EID와 프로젝트 revision에 연결됩니다.
6. **Blender / GLB** 또는 기존 FreeCAD/IFC 버튼으로 내보냅니다. 내보내기 영수증과 실제 파일을 함께 확인합니다. Blender의 바닥층은 원본에 유효한 slab footprint가 있을 때 생성됩니다. 난방관의 외곽 범위로 바닥을 임의 생성하지 않습니다.

## Codex에서 함께 작업하기

이 폴더를 Codex 프로젝트로 열면 `AGENTS.md`와 `.agents/skills/mep-dxf-review/SKILL.md`가 협업 방법을 제공합니다. 프로젝트 `.codex/config.toml`에는 로컬 MCP 서버가 설정되어 있습니다. 프로젝트 신뢰 설정을 허용한 뒤 새 작업을 열거나 MCP 서버를 다시 시작하면 도구가 로드됩니다. 현재 진행 중인 작업은 서버 목록이 자동 갱신되지 않을 수 있습니다.

예시 요청:

> 이 현장의 난방 DXF를 분석해줘. 실제 외경은 제조사 규격에 맞춰 확인하고, 서로 다른 평면을 구분해 설정을 제안해줘. 원본의 끊긴 곳은 표시하고 내 승인 없이 연결하지 마. GUI에서 수정·저장한 뒤 Blender와 GLB로 내보내줘.

도구의 흐름은 `inspect_mep_source → parse_dxf(use_ai=false, use_vision=false) → get_mep_profile → propose_mep_profile → GUI 검토/저장 → get_mep_diagnostics → 내보내기`입니다. `parse_dxf`에는 프로젝트 출력 폴더의 `json_out_path`를 지정하면 원본 도면 옆에 작업 파일이 생기는 것을 피할 수 있습니다. 제안은 원본 SHA-256 및 revision에 연결되며, 원본이나 수정이 바뀌면 오래된 제안을 적용하지 않습니다. 사용자 검토 후 적용과 요소별 설계 검토 완료는 서로 다른 상태입니다.

MCP 없이도 GUI의 설정 기능을 모두 사용할 수 있습니다. 개발자는 `mep_profile.inspect_mep_source`, `ProjectSession.configure_source`, `blender_runner.build_blender`를 호출할 수 있습니다. Python 환경에 ezdxf, Shapely 2.1 이상, mcp가 필요하고, Blender 내보내기는 설치된 Blender 4.2 이상을 탐색합니다. `python -c "import ezdxf,shapely,mcp"`로 의존성을 확인합니다. 다른 PC로 폴더를 옮기면 `.codex/config.toml`의 경로를 변경합니다.

## 검증의 의미와 지원 범위

- 단위 해석은 `drawing_units.py`를 공유합니다. 새 프로젝트는 DXF 헤더를 사용하고 명시적인 설정이 우선합니다. 주석은 비교 근거이며, 그 숫자만으로 mm 작성 도면이라고 판정하지 않습니다.
- 이전 버전의 프로젝트는 열기만 해도 크기가 바뀌지 않도록 기존 배율 정책을 유지합니다. 단위 확인 화면에서 저장해야 새 배율이 적용됩니다. 모델·조사·원본 겹쳐보기 모두 해당 프로젝트의 같은 배율을 사용합니다.
- 배율이 바뀌면 기존 원본 부재 수정은 재연결 검토 대상으로 보존합니다. 다른 원본이 이전 부재의 좌표 기반 EID를 받더라도 삭제·치수·승인이 넘어가지 않습니다. 수동 추가 형상은 mm 좌표를 유지하고 검토 완료 상태를 해제합니다. 선택 영역은 같은 원본 부분을 유지하도록 환산하며, 입력한 단면·설치 높이는 환산하지 않습니다.
- Codex는 `get_source_units`로 revision·원본 SHA-256·비교 근거를 읽고, 사용자가 구체적인 배율을 검토한 뒤에만 `set_source_units`를 사용할 수 있습니다. GUI·인증된 HTTP `/source-units`·MCP는 같은 `ProjectSession` 처리와 원자적 저장을 사용합니다.

- LINE, ARC, bulge 폴리라인, SPLINE/ELLIPSE와 중첩 블록 변환을 처리하고 원본 인스턴스를 추적합니다. 곡선은 명시적 현 오차로 샘플링하며, 해석 가능한 곡선의 실제 길이는 샘플 선분 길이와 분리합니다.
- 일치하는 끝점과 같은 치수·높이·계통의 경로만 연결합니다. 근접 틈, 교차점, 분기는 진단하며 임의 연결하지 않습니다. 닫히지 않은 외곽은 중심선으로 바꾸지 않습니다.
- V010은 잘못된 설비 형상·단면, V011은 원본/영역 검증 오류, V012는 설비 검토 항목입니다. 누락 및 가정이 남아 있는 결과는 검토 모델입니다.
- 자동 영역 후보는 보조입니다. 복잡한 도곽·상세도·혼합 레이어는 선택 영역과 규칙 조정이 필요합니다. 도면 표현이 규칙으로 분리되지 않으면 Codex가 근거와 미지원 항목을 설명합니다.
- 물량표의 배관 외경은 15.9 mm 같은 값을 그대로 유지합니다. 덕트 외곽의 둘레를 중심선 길이로 집계하지 않습니다. 공칭 회로 수와 원본의 물리적 연속 경로 수는 다를 수 있습니다.
- 네이티브 재열기/GLB 검사는 출력 형상 검증입니다. 수리·열·환기량 해석, 시공 상세·부속품 확정, 실제 공사 물량 승인을 의미하지 않습니다. 바닥층은 배관이 매립되는 구성 설명용이며 열해석용 비중첩 재료영역이 아닙니다.

# 쉽고 재미있는 루프 — 계획서 (2026-09-18)

목표(사용자, 2026-09-18): **2D 도면 → 3D 자동 모델링(MEP 포함) → 간섭체크 → 물량내역. 아주 쉽고, 재미있게. 빌드 뒤에 벽·배관을 많이 고치므로 수정도 쉬워야 한다.**

이 문서는 그 목표를 기준으로 저장소의 전제를 전부 다시 잰 결과와, 그에 따른 작업 순서다.
모든 사실은 이번 주에 코드에서 직접 읽었거나(파일:줄) 실측했고, 조사 에이전트 7개의 보고를 비판 에이전트 1개가 대조했다.
측정하지 않은 숫자는 적지 않았다. 고객 도면은 **개수·초**로만 적는다(공개 저장소).

---

## 0. 한 줄 결론

저장소는 **"틀리지 않는 것"** 에는 성공했고 **"쉽고 재미있는 것"** 에는 실패했다.
가장 싼 되돌림 지점은 규칙이나 출력 경로가 아니라 **(1) 브라우저 편집기, (2) 검토 항목의 버튼화, (3) 선언 표면(프로젝트 기본값)** 이다.
출력 경로 다섯 개 중 둘(Blender·Pascal)과 IFC 빌더 둘 중 하나(`ifc_builder.py`)는 동결한다.

"재미" 의 정의: **열기 → 수 초 안에 3D → 클릭하면 이유 → 버튼 하나로 고침 → 간섭·물량이 바로 바뀜.** 분 단위인 것은 전부 "납품" 버튼 뒤로.

## 3. 원칙 (전 단계 공통)

1. **편집은 프로젝트에만 산다.** FreeCAD·Blender 산출물은 손대지 않는다 — 다음 빌드에 지워지고 간섭·물량과 갈라진다.
2. **새 저장 동사를 만들지 않는다.** 이동·분할·결합은 `delete+add`, 값은 `overrides`. 파서·빌더·검증은 이미 그 둘을 안다.
3. **선언은 자기보고한다.** 기본값이 채운 값은 `declaration_basis` 에, 편집한 높이는 `overrides.elevation` 존재 자체가 신호(`height_basis` 가 `declared` 로 분류, `geom_contract.py:295-296`).
4. **읽는 순서는 한 곳에.** 재질: `overrides` > 레이어·프로필 선언(최상위) > 프로젝트 기본값. `construction_rules._material_of` 는 지금 최상위를 먼저 읽는다(`:48-51`) — 뒤집어야 한다(기본값을 최상위에 쓰면 편집을 가린다).
5. **프론트 변경은 묶어서 빌드한다.** `tests/test_preview_bundle.py` 가 `frontend/built/` 해시를 잠그므로 `frontend/src`·`vendor/edit_geometry.js` 를 건드린 커밋은 `npm run build` 결과를 함께 담는다. 세 단계(§4·§5·§6)가 다 프론트를 건드리니 가능한 한 하나의 리빌드로.
6. **새 ★ 절마다 잠그는 테스트 이름**(`docs/decisions/README.md` 규칙). 아래 각 단계에 이름을 적어 두었다.
7. **고객 데이터는 프로젝트 폴더에만.** 제안·결정·기본값에 레이어 이름이 실린다 — 픽스처는 합성 이름.

## 4. Phase 0 — 기반 (독립·작음·먼저)

### 0-A. 물량표 벽 두께 버그
- **사실:** `boq_export.py:71` `t = float(w.get("width_detected") or ov.get("width") or pw)` — 계약(`GC.width_of`, `geom_contract.py:243-248`: overrides → 신뢰되는 width_detected → params, `thin_pair` 는 불신) 과 **정반대**, `UNTRUSTED_WIDTH_REASONS` 무시. 높이는 이미 `GC.height_of`(`:59`).
- **실측:** 벽 664 골든 도면의 thin_pair 벽 7개 → BOQ **T0 ×4, T50 ×3**, `GC.width_of` 는 7개 모두 200. 빌더·간섭·미리보기는 전부 계약을 따르므로 **물량표만 다르다.** 두 번째 결함: `width_detected` 가 있으면 브라우저/레이어맵 두께 편집이 물량표에서 무시된다.
- **변경:** 1줄 — `t = GC.width_of(w, params, "wall")`.
- **테스트(신규 `tests/test_boq.py`):** `test_wall_thickness_follows_the_contract`(thin_pair 50 → T200, T0/T50 없음) · `test_override_beats_detected_width`(detected 250, override 300 → T300) · `test_boq_agrees_with_builder_width`(샘플 전 벽에서 `GC.width_of` = T 키).
- **문서:** `walls.md` 두께 우선순위 절의 잠금 목록에 `tests/test_boq.py` 추가(`README.md:54` 행).

### 0-B. 저장 한 번 = 파싱 한 번

- **유일한 직접 읽기:** `freecad_builder.py:1361` `_story_owner`·`:1348` `_at_floor`·`:1140` 피팅 레코드가 `rec['elevation']` 을 **원값**으로 읽어 층을 배정 → 편집으로 층 경계를 넘긴 배관은 형상은 움직이고 `IfcBuildingStorey` 는 옛 층. `rec['level']` 이 있으면 그것을 먼저 쓰므로(`:1362-1364`) 스택 프로젝트는 무사, **단일 도면 다층(z 군집)** 에서만 문제.

## 7. Phase 3 — 선언: 프로젝트 기본값 + 열 때 세 질문

### 3-A. 스키마와 저장 위치
- **사실:** 프로필은 `source.options.mep_profile`(`project_server.py:196`); `source.options` 의 **모든 키가 `parse(**options)` 로 풀린다**(`:35`, `stack_build.py:247`) → 새 키는 **먼저 `parse()` kwarg 가 있어야** 기존 프로젝트·골든 `project` 항목이 `TypeError` 로 안 죽는다. GUI 설정 폼은 프로필을 폼에서 재조립하므로(`mep_setup_ui._form_profile:557-575`) 프로필 **안**에 둔 키는 다음 저장에서 사라진다 → **프로필 밖** `source.options.defaults`.
- **스키마(전 키 선택, 기존 이름 재사용):**
  ```json
  {"version": 1,
   "mep": {"pipe": {"material": "강관", "nominal_size": "DN100", "service": "domestic_cold",
                    "insulation": {"grade": "나", "humid": false, "fluid_temp_c": 20}},
           "duct": {"material": "아연도금강판", "service": "supply_air"},
           "tray": {"material": "steel"}},
   "architecture": {"wall": {"material": "콘크리트"}, "column": {"material": "콘크리트"},
                    "slab": {"material": "콘크리트"}, "beam": {"material": "콘크리트"}}}
  ```
  검증: `service ∈ construction_rules.SERVICES`, `insulation` 은 프로필 행 규칙(`mep_profile.py:169-176`) 그대로, `material`·`nominal_size` 는 자유 문자열(인식은 `material_key`·`parse_dn` 이 규칙 시점에). **치수(폭·높이·지름)는 제외** — `params/DEFAULT_DIMS` 가 이미 덮고 `height_basis` 가 `assumed` 로 표시한다. **층고는 여기 아니라 `source['height']`(→ `level_height`)** — 이미 있는 길.
- **스탬프:** `rec['declaration_basis'] = {'material': 'project_default', 'service': 'project_default', ...}` — 기본값이 채운 키만 나열하는 **딕셔너리 하나**(`dims_assumed` 의 목록 방식과 같다; 키마다 `*_basis` 를 늘리지 않는다). `result['defaults_effective'] = {'source': defaults, 'applied': {'material': n, ...}}` 를 `tolerances_effective` 옆(`dxf_parser.py:3739`) 에.

### 3-B. 주입 지점 (한 파이프라인에 한 곳)
- **레이어맵(건축·MEP) 경로:** `annotate_mep` 이 아니다(params 가 없고 벽 페어링 전이라 최상위 필드가 병합에서 사라진다, `dxf_parser.py:265-267`). `level_height` 자리(`:3455`) 도 아니다 — 창대·인방 채움(`fill_around_openings`, `:3650`) 이 **그 뒤**에 생겨 기본값을 놓친다(비판 에이전트 지적). **채택: `:3650` 뒤 · 두 번째 `apply_edits`(`:3658`) 앞의 루프 하나** — 필드가 `None`/`''` 인 레코드만 **최상위**에 채우고 `declaration_basis` 스탬프.
- **왜 최상위인가:** `review_signature` 가 `overrides` 전체를 해시하므로(`element_id.py:258`) `overrides` 에 쓰면 확인한 부재 전부가 `review_changed` 로 뒤집힌다. 최상위는 `source_snapshot` 키에 없다(`:240-243`). `freecad_builder.set_ifc_props`(`:118`) 와 `construction_rules._material_of` 는 최상위를 폴백으로 읽는다.
- **프로필 경로:** `mep_profile._assign(rec, row, index, profile)`(`:640`) — `row.get(k) or defaults[cat].get(k)` (`_assign` 은 빈 값을 `''` 로 쓰므로 `not row.get(k)` 로 검사, `:642-643`), 같은 스탬프. `apply_mep_profile` 이 `defaults` 를 넘긴다(~3줄).
- **읽는 순서 고정(원칙 4):** `construction_rules._material_of`(`:48-51`) 를 `overrides` → 최상위 로 뒤집는다(1줄) + 테스트. `freecad_builder:118` 은 이미 그 순서.
- **영수증:** `receipt['declarations_defaulted'] = {'dn': n, 'material': n, 'service': n}` 를 `declarations_missing` 옆(`construction_rules.py:598-605`) 에 — 기본값이 채워도 **선언 공백은 계속 보인다**(`test_construction_rules.py:45` 의 `missing` 의미 유지).
- **소비자 표시:** `whyHtml`(`app.js:370-397`) 한 줄 "프로젝트 기본값: 재질, 용도"; BOQ `근거` 열(`construction_rules.py:357-359`, `:595-597`) 에 " · 재질=프로젝트 기본값" 접미; IFC `Pset_MEPParser` 에 `DeclarationBasis`(`freecad_builder.py:84-114`, V105 가 왕복 검사); `pascal_bridge._PROVENANCE`(`:100-112`)·`blender_builder` 통과 목록(`:106`) 에 토큰 1개; MCP `get_review_items` 에 필드 1개. **높이 basis(assumed/declared) 는 건드리지 않는다.**
- **`mep_setup_ui.py:150` 의 `material: 'PB'` 프리셋 제거.** 지금은 GUI 로 만든 모든 배관 규칙이 "선언된 것처럼" 보여 기본값이 영원히 발동하지 않는다.
- **정직한 기대치:** PB 배관은 기본값을 채워도 KCS 표 3.4-1 에 PB 가 없으므로 지지 간격 규칙은 `material_not_recognized` 로 건너뛴다. 바뀌는 것은 `*_undeclared` → `material_not_recognized`(**선언은 했고 표가 없다**는 정확한 신호) 와, `service`·DN 이 있으면 슬리브·배수 구배·소화전 관경 규칙이 산다.

## 11. 순서와 의존

```
0-A BOQ 1줄 ─┐
0-B 저장 1회 ─┼─ 독립, 하루 안
0-C 경계 강화 ┘
      │
1-A 높이 칸(+빌더 층 배정) ──► 1-B 평면 탭 설비 ──► 1-C 3D→평면   [프론트 리빌드 1회]
      │
2-A 파서 제안 구조 ──► 2-B layer_map_io + /layer-rule ──► 2-C 버튼·REASON   [리빌드 1회, 1-x 와 합치면 더 좋다]
      │
3-A parse(defaults=) kwarg ──► 3-B 주입·읽는 순서·영수증 ──► 3-C 서버·MCP ──► 3-D GUI 세 질문·폼   [리빌드: whyHtml]
      │
4 물량 라이브 (0-A·0-B 뒤, 3 과 무관하게 가능)
      │
5 동결·메뉴·문서 (언제든, 마지막에 몰아서)
```
2-A 는 파서만 건드리므로 1-x 와 병행 가능. 3-A 는 **3 의 어떤 것보다 먼저**(마이그레이션 안전).

## 13. 위험과 대응

| 위험 | 대응 |
|---|---|
| `pair_min=median/3` 원클릭이 진짜 얇은 벽을 떨어뜨린다 | 2-A 에서 골든 도면 적용 전후 벽 수를 먼저 재고, 버튼 문구에 "레이어 전체에 적용" |
| 기본값을 `overrides` 에 쓰면 확인한 부재가 전부 `review_changed` | 최상위 + 후단 루프(3-B), `test_project_default_does_not_change_review_signature` |
| 기본값이 편집을 가린다 | `_material_of` 읽는 순서 뒤집기(원칙 4) + 테스트 |
| `source.options.defaults` 가 옛 프로젝트에서 `TypeError` | 3-A 를 3 의 첫 커밋으로; 골든 `project` 항목이 게이트 |
| 층고 답이 파라펫·허리벽·인방을 덮는다 | 빈칸 기본, 인방 테스트, 레이어맵 `height` 있는 행은 덮지 않는 옵션 검토 |
| 이동한 배관의 joints 상실 → V012 소음 | 결정 2(a) 로 시작해 골든에서 세고 (b) 로 갈지 결정 |
| 높이 편집이 층을 넘는데 IFC storey 는 옛 층 | 1-A 의 `freecad_builder` 세 곳 수정 + skip-guarded 테스트 |
| 프론트 리빌드 누락으로 게이트 빨강 | 원칙 5, 단계마다 리빌드 커밋 하나 |
| 고객 레이어명이 제안·결정·기본값에 실린다 | 프로젝트 폴더에만; 픽스처는 합성 이름; 커밋 전 diff·메시지 스캔 |
| 라이브 BOQ 가 MEP 섹션에서 느리다 | 4 에서 골든 `.mep` 로 먼저 측정, 조건부 활성 |

## 14. 하지 않을 것 (이 계획의 범위 밖)

- 3D 에서 끝점 끌기. 새 저장 동사. LLM 이 그리는 것.
- 외경→DN 역산, 계통 이름→용도, **카테고리→재질** 추정(프로젝트 기본값은 추정이 아니라 사람이 적은 선언이다).
- 시공기준 규칙 추가(Phase 2~5 는 선언이 들어오면 산다). 피팅 치수표. `pair_max` 상향. 0 mm 간섭 판정 변경.
- 브라우저 GLB. Blender 개구부 절삭 이식. Pascal 확장.
- ~~`ifc_builder` 개구부/MEP 추가.~~ **2026-09-21 뒤집음** — 이 줄의 전제("개구부 불리언과 MEP 는
  FreeCAD 커널이 필요하다")가 실측으로 깨졌다. 개구부는 IFC 에서 절삭이 아니라 **선언**이고,
  FreeCAD 경로도 IFC 에는 같은 void 선언만 실었다. `ifc_builder.py` 가 납품 경로가 되고
  `freecad_builder.py` 가 동결됐다 — 경위는 [ifc-builder.md](../decisions/ifc-builder.md).
- V 코드를 브라우저 상태에 넣는 것(저장마다 검증 패스 추가 — 필요가 측정되면).
- 새 UI 프레임워크. 4D 기간·품셈 수치.
